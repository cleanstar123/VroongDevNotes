## 1. 발생 경위

> [!info] 배경
>
> - 라이더 앱에서 출금 버튼 클릭 시 중복 클릭 방지(debounce) 처리가 없음
> - 라이더가 실패 응답을 기다리는 동안 출금 버튼을 반복 클릭하여 **약 3분간 7건의 출금 요청** 발생
> - 두 개의 ECS 인스턴스(A, B)에 분산 처리됨

> [!warning] 문제
>
> - 헥토 응답코드 `VTIM(원천사 타임아웃)`은 **은행이 응답을 못 한 것**이지만, 실제로는 은행에서 이체가 처리된 후 응답만 누락된 경우가 존재
> - `VTIM` 응답 시 서버 코드(`MobWithdrlUseCase`)는 `RuntimeException`을 throw → `@Transactional` rollback → `vr_withdrl_list`, `vr_account_mst` **미기록**
> - `vr_withdraw_request_his`는 `REQUIRES_NEW` 트랜잭션으로 rollback 대상 아님 → **7건 모두 기록됨**
> - 결과적으로 실이체가 됐음에도 내부 원장에 반영 안 된 건 발생

## 5. 코드 동작 원리

> [!info] requestWithdrl 처리 순서
>
> ```
> 1. 계좌 잔액 조회 (비관적 락)
> 2. vr_withdrl_list INSERT      ← 헥토 호출 전 먼저 저장
> 3. vr_account_mst INSERT       ← 헥토 호출 전 먼저 저장
> 4. 헥토 API 호출
> 5. vr_withdraw_request_his INSERT (REQUIRES_NEW — 무조건 커밋)
> 6. 헥토 결과 0000 아니면 RuntimeException throw
>    → @Transactional rollback → 2, 3번 INSERT 취소
> 7. 성공 시 vr_withdrl_list.WITHRAW_REQ_SEQ_NO 업데이트
> ```
>
> - VTIM 실패 시 rollback → 내부 원장 미반영 (의도된 동작)
> - **문제: 실제로 은행 이체가 됐음에도 원장에 기록 안 됨**
