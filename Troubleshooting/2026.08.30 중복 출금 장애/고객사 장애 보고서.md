## 3. 원인 분석

이번 장애는 두 가지 원인이 복합적으로 작용하였습니다.

### 원인 1 — 앱 중복 클릭 방지 미비

출금 버튼을 빠르게 반복 클릭하더라도 서버에 중복 요청이 전송되는 구조였습니다. 라이더가 첫 번째 요청의 응답을 기다리는 동안 버튼을 여러 번 눌러 7건이 발생하였습니다.

### 원인 2 — VTIM(은행 응답 지연) 처리 로직의 구조적 한계

결제사(헥토)의 응답 코드 중 **VTIM**은 "은행이 정해진 시간 내에 응답하지 않았음"을 의미합니다. 이 경우 두 가지 상황이 존재합니다.

- **실제로 이체가 됐지만** 은행이 응답을 늦게 보낸 경우 → VTIM
- **실제로 이체가 안 된** 경우 → VTIM

기존 시스템은 VTIM 응답을 받으면 **무조건 실패로 처리**하여 내부 원장(출금 내역)을 기록하지 않았습니다. 이로 인해 1번 요청(30128)처럼 실제 은행 이체가 완료된 건임에도 내부 원장에 반영되지 않는 상황이 발생하였습니다.

```
기존 처리 흐름:
헥토 VTIM 응답 → 무조건 실패 처리 → 원장 미기록
                                    ↑
                          실이체 여부 확인 없음 (문제)
```

### 대책 1 — VTIM 자동 검증 및 원장 자동 반영 시스템 구축

```
개선된 처리 흐름:

헥토 VTIM 응답
    │
    ▼
대기 테이블 저장 (vr_withdraw_vtim_pending)
    │
    ▼  [60초마다 자동 실행]
헥토에 실이체 여부 조회
    │
    ├── 이체 완료 확인 → 원장 자동 반영 ✅
    ├── 미이체 확인   → 미이체로 확정 기록 ✅
    └── 응답 지연 중  → 최대 10분간 재시도
                         (10분 후에도 미확인 시 관리자 이메일 자동 발송)
```

**이번 장애에 적용했다면:**
