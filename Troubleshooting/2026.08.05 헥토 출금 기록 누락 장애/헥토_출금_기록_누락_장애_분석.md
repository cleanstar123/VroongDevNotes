### ⚠️ 중요: 출금(송금) 비동기 결과 콜백 없음

`입금노티`는 **외부에서 우리 예치금 가상계좌로 돈이 입금될 때** 헥토가 보내는 알림이며,
**라이더 출금(송금) 성공/실패 결과를 비동기로 통보하는 콜백 수단은 존재하지 않는다.**
출금 최종 결과는 우리가 **결과조회(V1) API를 능동적으로 호출**해야만 확인 가능하다.

### 원인

```
출금 요청 → Hecto 송금 API(/pyag/v1/fxTransKrw) 호출
    ↓ (자정 한국 은행 점검시간 → PY11 응답 수신)
vr_withdraw_request_his에 PY11 기록 저장 (또는 무기록)
    ↓
[BUG] 우리 시스템: PY11 = 실패로 간주, 처리 종료
    ↓
은행 점검 해제 후, Hecto가 해당 거래를 최종 처리 완료 (status=21)
    ↓
우리 시스템은 결과조회(V1) API를 호출하지 않았으므로 성공 여부를 알 수 없음
    ↓
vr_withdrl_list, vr_account_mst에 INSERT 안 됨
```

**스펙 근거:** 헥토 공식 스펙은 `VTIM(원천사 타임아웃)` 응답 시 반드시 결과조회(V1)를 호출하도록 명시하고 있으며, 은행 점검/장애 시 최종 확정이 지연될 수 있음을 경고한다. `PY11(은행 점검시간)` 역시 동일한 맥락의 미확정 상태이나, 우리 시스템이 이를 처리 종료로 잘못 판단하고 결과조회를 수행하지 않았다.

**입금노티(콜백) 부재 확인:** 스펙상 출금(송금) 결과에 대한 비동기 콜백 수단은 존재하지 않는다. 따라서 "콜백 누락"이 아닌, **결과조회 API 미호출**이 실제 원인이다.

## 근본 원인 수정 방향

### 패턴 A 수정

**단기 (즉시 적용 가능):**
- 출금 API 응답이 `PY11` 또는 `VTIM`인 경우, 일정 시간 후 결과조회(V1) API(`/pyag/v1/fxResult`)를 호출하여 최종 status를 확인하는 로직 추가
- 결과조회 응답 `status=29` (송금처리중)이면 재조회 스케줄링, `status=21` (성공)이면 `vr_withdrl_list` / `vr_account_mst` INSERT 수행

**중기 (배치):**
- 헥토 `mchtTrdNo` 기준으로 우리 `vr_withdraw_request_his`와 헥토 결과조회를 대사(reconciliation)하는 야간 배치 도입
- 결과 미확정 건(PY11, VTIM, 미기록)을 자동으로 재조회하여 성공 건 수동 보정 없이 처리

### 패턴 B 수정

**단기:**
- 출금 API 응답 성공(0021) 직후 DB INSERT 실패 시, 트랜잭션 재시도 또는 Dead Letter Queue에 저장하여 재처리
- 위 패턴 A의 배치 대사 로직이 패턴 B도 동시 커버 — 성공 응답이 헥토에 있고 우리 DB에 없는 건을 모두 보정 가능
