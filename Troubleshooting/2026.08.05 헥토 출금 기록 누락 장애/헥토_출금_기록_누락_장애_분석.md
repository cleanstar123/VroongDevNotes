## 패턴 A: 헥토 자정 재시도 → 콜백 DB INSERT 누락

### 원인

```
출금 요청 → Hecto API 호출
    ↓ (자정 한국 은행 점검시간 PY11 응답 수신)
vr_withdraw_request_his에 PY11 실패 기록 저장 (또는 무기록)
    ↓
Hecto 내부적으로 재시도 예약
    ↓ (01:00~01:30경 은행 점검 해제 후 Hecto 자동 재처리 성공)
Hecto → 우리 콜백 엔드포인트 호출 (OUT_STAT_CD=0021)
    ↓
[BUG] 콜백 처리 로직이 이미 처리된 것으로 판단하거나
      원래 vr_withdraw_request_his 기록을 찾지 못해 DB 기록 생략
    ↓
vr_withdrl_list, vr_account_mst에 INSERT 안 됨
```

**은행 점검 시간대:** 한국 은행 점검은 자정~00:30 사이에 발생하며,
이 시간대에 요청된 출금은 PY11 응답을 받고 Hecto가 내부적으로 재시도를 수행함.
이 재시도 성공 콜백이 우리 시스템에서 정상 처리되지 않는 버그.

## 패턴 B: 서버 트랜잭션 롤백 → DB 기록 전체 누락

### 원인

```
우리 서버 → Hecto API 출금 요청 전송
                ↓
           Hecto: 처리 성공 (은행 송금 완료)
                ↓
    Hecto 응답 수신 중 우리 서버 장애 발생
    (DB connection timeout / OOM / pod restart 등)
                ↓
  vr_withdraw_request_his INSERT → 롤백
  vr_withdrl_list W/F INSERT → 롤백
                ↓
  Hecto는 이미 은행 송금 완료
  우리 DB에는 아무 기록도 없음
```

패턴 A와의 결정적 차이: **vr_withdraw_request_his에 요청 기록 자체가 없음.**
패턴 A는 PY11 실패 기록이라도 존재하지만, 패턴 B는 Hecto API를 호출한 흔적 자체가 없음.

## 공통 영향 범위

- `vr_withdrl_list`: W(출금), F(수수료) 기록 누락
- `vr_account_mst`: 잔액 추적 기록 누락 → BAL_AMT 오류 발생 가능

## 근본 원인 수정 방향

### 패턴 A 수정
- Hecto 콜백 수신 시 `vr_withdraw_request_his`에 해당 `MCHT_TRD_NO`(거래번호)로 기존 기록을 찾지 못하는 경우에도 정상 처리하도록 콜백 핸들러 로직 보강
- PY11 응답 시 재시도 예약 상태를 별도로 추적하여 Hecto 재시도 성공 콜백을 누락 없이 처리

### 패턴 B 수정
- Hecto API 응답 성공 후 DB INSERT 트랜잭션 실패 시 재처리 메커니즘 필요
- Hecto 거래번호(`MCHT_TRD_NO`) 기준으로 우리 DB와 Hecto 기록을 주기적으로 대사(reconciliation)하는 배치 로직 도입 검토
