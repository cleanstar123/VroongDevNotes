## 1. 변경 전 vs 변경 후 비교

### 1-1. `batchUpdateEndDayByContEdDate()` — VrDeductMstQueryDslRepository

| 항목      | 변경 전                                 | 변경 후                               |
| ------- | ------------------------------------ | ---------------------------------- |
| **동작**  | END_DAY를 계약종료일로 덮어쓰고 USE_YN = 'N' 설정 | END_DAY는 건드리지 않고 USE_YN = 'N' 만 설정 |
| **문제점** | 원본 일차감 기간 정보(END_DAY) 유실             | —                                  |
| **장점**  | —                                    | 원본 기간 보존 → 잔여 횟수 계산에 오류 없음         |

```sql
-- 변경 전 (END_DAY 덮어씀)
UPDATE vr_deduct_mst
SET end_day = '2026-10-14',   -- 계약종료일로 덮어씀 → 원본 소실
    use_yn = 'N',
    upd_user = 'BATCH',
    upd_date = NOW()
WHERE rider_id = 'l9890724'
  AND start_day <= '2026-10-14'
  AND end_day >= '2026-10-14'
  AND use_yn = 'Y';

-- 변경 후 (END_DAY 유지)
UPDATE vr_deduct_mst
SET use_yn = 'N',             -- USE_YN만 변경, END_DAY 원본 보존
    upd_user = 'BATCH',
    upd_date = NOW()
WHERE rider_id = 'l9890724'
  AND start_day <= '2026-10-14'
  AND end_day >= '2026-10-14'
  AND use_yn = 'Y';
```

### 1-2. `countActualDeductionsBySeqNo()` → `countActualDeductionsBySeqNoAndName()` — VrDeductDailyQueryDslRepository

| 항목        | 변경 전                                                   | 변경 후                                                                             |
| --------- | ------------------------------------------------------ | -------------------------------------------------------------------------------- |
| **필터 조건** | DEDUCT_SEQ_NO 만                                        | DEDUCT_SEQ_NO + DEDUCT_NAME 모두                                                   |
| **문제점**   | 동일 SEQ_NO에 다른 이름의 일차감이 붙으면 횟수 오산 가능                    | —                                                                                |
| **메서드명**  | `countActualDeductionsBySeqNo(BigDecimal deductSeqNo)` | `countActualDeductionsBySeqNoAndName(BigDecimal deductSeqNo, String deductName)` |

```java
// 변경 전
public long countActualDeductionsBySeqNo(BigDecimal deductSeqNo) {
    return queryFactory
        .select(qDeductDaily.count())
        .from(qDeductDaily)
        .where(qDeductDaily.deductSeqNo.eq(deductSeqNo))  // SEQ_NO만
        .fetchOne();
}

// 변경 후
public long countActualDeductionsBySeqNoAndName(BigDecimal deductSeqNo, String deductName) {
    return queryFactory
        .select(qDeductDaily.count())
        .from(qDeductDaily)
        .where(
            qDeductDaily.deductSeqNo.eq(deductSeqNo)
                .and(qDeductDaily.deductName.eq(deductName)))  // SEQ_NO + DEDUCT_NAME 동시 검증
        .fetchOne();
}
```

## 3. 구체적인 예시 시나리오

> `DEDUCT_CNT` = 총 적용 **일 수** (일차감). 배치가 실행되는 날 하루에 한 번씩 차감되며,
> `START_DAY` 이후 `END_DAY` 이전 범위 안에서 `DEDUCT_CNT`가 소진될 때까지 적용됩니다.

## 4. 중복 방지 (Idempotency)

배치가 같은 날 여러 번 실행되더라도 동일한 일차감이 중복 생성되지 않도록 아래 조건을 기준으로 체크합니다.

```java
// existsCarryOverDeductForSupplier() 내부 조건
WHERE supp_id = 'SUP002'
  AND rider_id = 'l9890724'
  AND use_yn = 'Y'
  AND start_day = '2025-11-01'
  AND deduct_name = '오토바이 할부금'
```

이미 동일 조건의 행이 존재하면 INSERT를 건너뜁니다.
