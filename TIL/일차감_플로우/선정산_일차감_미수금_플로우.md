## 2. 주요 필드 의미

### vr_rider_acct_daily

| 필드 | 의미 |
|------|------|
| `DEDUCT_VAL` | 실제 차감된 일차감 총액 (배달료 + 잔액에서 차감된 합) |
| `BALANCE_DEDUCT_AMT` | 잔액에서 차감된 일차감 유보분 (full-or-nothing 결과) |
| `UNPAID_RECOVERY_AMT` | 이월 미수금 중 배달료 풀에서 회수한 금액 |
| `BAL_RECOVER_AMT` | 이월 미수금 중 잔액·TI송금·D입금으로 회수한 금액 |
| `RECOVER_AMT` | `UNPAID_RECOVERY_AMT + BAL_RECOVER_AMT + D입금회수분` 합계 |

### PreSettlementLedgerContext (배치 내부 record)

```java
private record PreSettlementLedgerContext(
    BigDecimal prevUnpaidAmt,       // 배치 실행 전 이월 미수금 (음수 저장)
    BigDecimal currentBalAmt,       // 현재 잔액
    BigDecimal unpaidRecoveryAmt,   // 배달료 풀에서 회수한 미수금
    BigDecimal balanceDeductAmt,    // 잔액에서 차감된 일차감 유보분
    BigDecimal balRecoverAmt,       // 잔액(+TI)에서 회수한 미수금
    BigDecimal newUnpaidAmt,        // 배치 후 새 미수금 (음수 또는 0)
    BigDecimal depositRecoverAmt)   // D입금으로 회수된 금액
```

## 3. 선정산 배치 계산 흐름

```
totDeliveryAmt (총 배달료)
    ↓
본사수수료, 협력사수수료, 보험료, 세금 차감
    ↓
settlementPool (일차감 이전 정산 가능 금액)
    │
    ├─ [Step 1] 이월 미수금 배달료 회수
    │    unpaidRecoveryAmt = min(pool, |prevUnpaidAmt|)
    │    poolAfterUnpaid = pool - unpaidRecoveryAmt
    │
    ├─ [Step 2] 일차감 적용 (Largest Fits First)
    │    풀에 들어갈 수 있는 일차감부터 순서대로 차감
    │    actualDeductVal = 실제 차감된 합 → DEDUCT_VAL 기록
    │    todayDeferred = 풀 부족으로 못 차감된 잔여 일차감
    │
    └─ [Step 3] 잔액으로 유보분 처리 (Full-or-Nothing)
         if (잔액 >= todayDeferred):
             balanceDeductAmt = todayDeferred   → 잔액에서 전액 차감
             deferredAfterBalance = 0
         else:
             balanceDeductAmt = 0               → 잔액에서 한 푼도 안 차감
             deferredAfterBalance = todayDeferred → 전액 미수금으로 이월
```

> **Full-or-Nothing 이유**: 잔액을 일부만 빼면 이후 출금 시 잔액 계산이 틀어지므로, 잔액이 충분할 때만 전액 차감한다.

---

## 4. 미수금 계산 공식

```
newUnpaidAmt = prevUnpaidAmt
               + unpaidRecoveryAmt   (배달료로 회수)
               + balRecoverAmt       (잔액으로 회수)
               - deferredAfterBalance (새로 발생한 미수금)

if (newUnpaidAmt > 0): newUnpaidAmt = 0   ← 양수는 0으로 강제 (미수금은 음수만 허용)
```

- `vr_account_mst.UNPAID_AMT`에 음수로 저장
- 미수금 없으면 `null`

## 5. 케이스별 예시 (모든 경우의 수)

> **공통 전제**  
> - 일차감 규칙: 5,000원  
> - 이월 미수금은 음수로 표기 (예: `-3,000` = 미수금 3,000원)

---

### Case 1. 배달료에서 일차감 + 미수금 모두 해소

**조건**: 이월 미수금 있음, 배달료 > 일차감 + 미수금

```
prevUnpaidAmt = -3,000
settlementPool = 10,000
잔액(balAmt) = 5,000

Step 1) unpaidRecoveryAmt = min(10,000, 3,000) = 3,000
        poolAfterUnpaid = 10,000 - 3,000 = 7,000

Step 2) actualDeductVal = 5,000 (일차감 전액 배달료에서 차감)
        todayDeferred = 0

Step 3) balanceDeductAmt = 0 (유보분 없음)
        deferredAfterBalance = 0

결과:
  DEDUCT_VAL          = 5,000
  UNPAID_RECOVERY_AMT = 3,000
  BALANCE_DEDUCT_AMT  = 0
  BAL_RECOVER_AMT     = 0
  newUnpaidAmt        = 0 (미수금 완전 해소)
  잔액 변동 없음
```

---

### Case 2. 배달료에서 일차감만 해소 (미수금 없음)

**조건**: 이월 미수금 없음, 배달료 > 일차감

```
prevUnpaidAmt = 0
settlementPool = 8,000
잔액(balAmt) = 5,000

Step 1) unpaidRecoveryAmt = 0 (미수금 없음)
        poolAfterUnpaid = 8,000

Step 2) actualDeductVal = 5,000
        todayDeferred = 0

Step 3) balanceDeductAmt = 0
        deferredAfterBalance = 0

결과:
  DEDUCT_VAL          = 5,000
  UNPAID_RECOVERY_AMT = 0
  BALANCE_DEDUCT_AMT  = 0
  newUnpaidAmt        = 0
```

---

### Case 3. 배달료에서 미수금 부분 해소 후 일차감도 차감

**조건**: 이월 미수금 있음, 배달료가 미수금은 일부 회수 + 일차감까지 처리 가능

```
prevUnpaidAmt = -8,000
settlementPool = 6,000
잔액(balAmt) = 10,000

Step 1) unpaidRecoveryAmt = min(6,000, 8,000) = 6,000
        poolAfterUnpaid = 6,000 - 6,000 = 0

Step 2) actualDeductVal = 0 (풀이 0이므로 일차감 못 차감)
        todayDeferred = 5,000 (일차감 전액 유보)

Step 3) 잔액(10,000) >= todayDeferred(5,000)
        balanceDeductAmt = 5,000   ← 잔액에서 전액 차감
        deferredAfterBalance = 0

결과:
  DEDUCT_VAL          = 0 + 5,000 = 5,000  (배달료 0 + 잔액 5,000)
  UNPAID_RECOVERY_AMT = 6,000  (배달료로 미수금 6,000 회수)
  BALANCE_DEDUCT_AMT  = 5,000
  newUnpaidAmt        = -8,000 + 6,000 + 0 - 0 = -2,000  (남은 미수금)
  잔액 -= 5,000
```

---

### Case 4. 배달료에서 미수금 일부 회수, 일차감을 잔액에서 차감

**조건**: Case 3과 동일하나, 이월 미수금이 더 작아 배달료 풀이 남는 경우

```
prevUnpaidAmt = -2,000
settlementPool = 6,000
잔액(balAmt) = 10,000

Step 1) unpaidRecoveryAmt = min(6,000, 2,000) = 2,000
        poolAfterUnpaid = 4,000

Step 2) actualDeductVal = 4,000 (풀 4,000에서 일차감 5,000 중 4,000만 가능)
        todayDeferred = 1,000 (나머지 1,000 유보)

Step 3) 잔액(10,000) >= todayDeferred(1,000)
        balanceDeductAmt = 1,000
        deferredAfterBalance = 0

결과:
  DEDUCT_VAL          = 4,000 + 1,000 = 5,000
  UNPAID_RECOVERY_AMT = 2,000
  BALANCE_DEDUCT_AMT  = 1,000
  newUnpaidAmt        = -2,000 + 2,000 - 0 = 0
  잔액 -= 1,000
```

---

### Case 5. 배달료 부족, 잔액도 부족 → 미수금 발생

**조건**: 배달료로 일차감 일부 처리, 잔액도 나머지를 못 감당

```
prevUnpaidAmt = 0
settlementPool = 1,000
잔액(balAmt) = 3,000

Step 1) unpaidRecoveryAmt = 0
        poolAfterUnpaid = 1,000

Step 2) actualDeductVal = 1,000 (풀 1,000에서 일차감 5,000 중 1,000)
        todayDeferred = 4,000

Step 3) 잔액(3,000) < todayDeferred(4,000)
        balanceDeductAmt = 0   ← Full-or-Nothing: 잔액에서 한 푼도 안 차감
        deferredAfterBalance = 4,000

결과:
  DEDUCT_VAL          = 1,000
  BALANCE_DEDUCT_AMT  = 0
  newUnpaidAmt        = 0 - 0 - 0 - 4,000 = -4,000  (신규 미수금)
  잔액 변동 없음
```

---

### Case 6. 배달료 0건, 미수금만 있음 → 잔액에서 미수금 회수

**조건**: 해당 일 배달 없음, 이월 미수금 존재, 잔액이 충분

```
prevUnpaidAmt = -5,000
settlementPool = 0
잔액(balAmt) = 8,000

Step 1) unpaidRecoveryAmt = 0 (풀이 0)
        poolAfterUnpaid = 0

Step 2) actualDeductVal = 0, todayDeferred = 5,000

Step 3) 잔액(8,000) >= todayDeferred(5,000)
        balanceDeductAmt = 5,000
        deferredAfterBalance = 0

        잔액에서 미수금 회수:
        remainingUnpaid = 5,000 - 0 = 5,000
        balRecoverAmt = min(잔액 - balanceDeductAmt, remainingUnpaid)
                      = min(8,000 - 5,000, 5,000) = min(3,000, 5,000) = 3,000

결과:
  DEDUCT_VAL          = 5,000 (일차감 5,000원 → 미수금 유보분으로 잔액 차감)
  BALANCE_DEDUCT_AMT  = 5,000
  BAL_RECOVER_AMT     = 3,000 (잔액 남은 금액으로 미수금 3,000 추가 회수)
  newUnpaidAmt        = -5,000 + 0 + 3,000 - 0 = -2,000
  잔액 -= (5,000 + 3,000) = -8,000
```

> 이 케이스는 일차감과 미수금이 함께 잔액에서 빠지는 상황.

---

### Case 7. 배달료·잔액 모두 부족 → 미수금 + 이전 미수금 누적

```
prevUnpaidAmt = -3,000
settlementPool = 500
잔액(balAmt) = 2,000

Step 1) unpaidRecoveryAmt = min(500, 3,000) = 500
        poolAfterUnpaid = 0

Step 2) actualDeductVal = 0, todayDeferred = 5,000

Step 3) 잔액(2,000) < todayDeferred(5,000)
        balanceDeductAmt = 0
        deferredAfterBalance = 5,000

        balRecoverAmt:
        remainingUnpaid = 3,000 - 500 = 2,500
        잔액 남음 = 2,000 - 0 = 2,000
        balRecoverAmt = min(2,000, 2,500) = 2,000

결과:
  DEDUCT_VAL          = 0
  UNPAID_RECOVERY_AMT = 500
  BAL_RECOVER_AMT     = 2,000
  newUnpaidAmt        = -3,000 + 500 + 2,000 - 5,000 = -5,500
  잔액 -= 2,000
```

### Case 8. D타입 입금으로 미수금 완전 해소

> 실시간 처리 (`MobWithdrlUseCase.java`)

```
prevUnpaidAmt = -10,000
balAmt = 5,000
prevEffectiveBal = 5,000 + (-10,000) = -5,000
입금액(reqVal) = 8,000

effectiveBal = -5,000 + 8,000 = 3,000 ≥ 0  → 완전 해소

결과:
  newBalAmt   = 3,000
  newUnpaidAmt = null (해소)
  amountRecovered = |-10,000| = 10,000

→ addRecoverAmtForDeposit(suppId, riderId, 10,000, 10,000, seqNo)
  : 가장 최근 vr_rider_acct_daily row에 RECOVER_AMT + 10,000 임시 반영

→ 익일 배치 실행 시:
  subtractDepositRecoveryFromPrevRow()  : 이전 row에서 10,000 차감
  findDepositRecoveryAmtForRiderOnDate(): 입금일 row에 10,000 반영
  updateDeductDailyForRecovery(10,000)  : vr_deduct_daily UNPAID_AMT 소급
```

### Case 9. D타입 입금으로 미수금 부분 해소

```
prevUnpaidAmt = -10,000
balAmt = 2,000
prevEffectiveBal = 2,000 + (-10,000) = -8,000
입금액(reqVal) = 5,000

effectiveBal = -8,000 + 5,000 = -3,000 < 0  → 부분 해소

결과:
  newBalAmt    = 0
  newUnpaidAmt = -3,000
  amountRecovered = |-10,000| + (-3,000) = 7,000
                  = 해소된 미수금 = 10,000 - 3,000

→ addRecoverAmtForDeposit(suppId, riderId, 7,000, 10,000, seqNo)
```

### Case 10. TI타입 송금으로 미수금 완전 해소

> `MobWithdrlUseCase.java` TI 처리 부분

```
수신자(라이더):
  receiverPrevUnpaid = -6,000
  receiverBalAmt     = 1,000
  receiverPrevEffectiveBal = 1,000 + (-6,000) = -5,000
  송금 수신액(reqVal) = 8,000

receiverEffectiveBal = -5,000 + 8,000 = 3,000 ≥ 0  → 완전 해소

결과:

  receiverNewUnpaid  = null
```

## 6. D타입 입금 vs TI타입 처리 비교

| 항목 | D타입(직접 입금) | TI타입(송금 입금) |
|------|----------------|-----------------|
| **vr_rider_acct_daily 반영** | 가장 최근 row에 **임시** 반영 → 익일 배치에서 이전 | RP 배치에서 `findTiRecoveryAmtForRiderOnDate()`로 조회 반영 |
| **vr_deduct_daily 소급** | 익일 배치 (`depositRecoverAmt` 경로, `maxTranDay` 제한) | 실시간 즉시 반영 (`updateDeductDailyForRecovery`) |
| **미수금 조건 트리거** | `prevEffectiveBal < 0` | `receiverPrevUnpaid < 0` |
| **회수분 계산** | `totalOutstanding + effectiveBal` (부분) | 동일 |

## 7. 미수금 소급 반영 흐름 (vr_deduct_daily)

```
updateDeductDailyForRecovery(suppId, riderId, totalRecovery, maxTranDay)
  → vr_deduct_daily에서 UNPAID_AMT > 0 인 row를 FIFO (발생일 오름차순) 조회
  → 순서대로 UNPAID_AMT를 줄이고 DEDUCT_AMT를 늘림
  → 주정산 SUM(DEDUCT_AMT) = 실제 징수된 일차감과 일치하도록 맞춤

maxTranDay 파라미터:
  - null: 전체 row 대상 (TI 실시간 처리)
  - 당일 날짜: 오늘 이전 row만 대상 (배치, 당일 신규 row 오염 방지)
```

## 8. D타입 입금 2-Phase 처리 상세

```
Phase 1 (실시간 입금 시)
  addRecoverAmtForDeposit()
    → 가장 최근 vr_rider_acct_daily row에 RECOVER_AMT, BAL_RECOVER_AMT 임시 +

Phase 2 (익일 배치 실행 시 - BaeminToVroongIfUseCase)
  1. 입금일(deliveryDate) row 신규 생성
  2. depositRecoverAmt = findDepositRecoveryAmtForRiderOnDate()
  3. 입금일 row에 depositRecoverAmt 반영
  4. subtractDepositRecoveryFromPrevRow()
       → 이전 row의 RECOVER_AMT, BAL_RECOVER_AMT에서 depositRecoverAmt 차감 (정리)
  5. updateDeductDailyForRecovery(depositRecoverAmt, maxTranDay=deliveryDate)
       → vr_deduct_daily 소급 (입금일 이전 row만 대상)
```

## 9. 전체 플로우 다이어그램

```
[매일 선정산 배치 - BaeminToVroongIfUseCase]

라이더별 반복:
  1. 총 배달료 계산 (totDeliveryAmt)
  2. 수수료·세금 차감 → settlementPool
  3. 이월 미수금 조회 (prevUnpaidAmt)
  4. 배달료 풀에서 미수금 회수 (unpaidRecoveryAmt)
  5. 일차감 Largest-Fits-First 적용 → actualDeductVal, todayDeferred
  6. 잔액 조회 (currentBalAmt)
  7. Full-or-Nothing으로 잔액에서 유보분 처리
       - 가능: balanceDeductAmt = todayDeferred
       - 불가: balanceDeductAmt = 0, 전액 미수금 이월
  8. 잔액에서 남은 미수금 회수 (balRecoverAmt)
  9. D입금 회수분 조회·반영 (depositRecoverAmt)
  10. newUnpaidAmt 계산
  11. vr_rider_acct_daily 저장
  12. vr_account_mst(RP타입) 저장 → 잔액·미수금 원장 반영
  13. vr_deduct_daily 소급 반영 (balRecoverAmt, depositRecoverAmt)

[실시간 D타입 입금 - MobWithdrlUseCase / HectoDepositUseCase]

  1. 미수금 조회 (prevUnpaidAmt)
  2. 유효 잔액 = balAmt + prevUnpaidAmt + 입금액
  3. vr_account_mst(D타입) 저장
  4. amountRecovered 계산 (완전/부분 해소)
  5. addRecoverAmtForDeposit() → 이전 row 임시 반영
  → 익일 배치에서 subtractDepositRecoveryFromPrevRow()로 정리

[실시간 TI타입 송금 - MobWithdrlUseCase]

  수신자:
  1. 미수금 조회 (receiverPrevUnpaid)
  2. 수신 유효 잔액 계산
  3. vr_account_mst(TI타입) 저장
  4. amountRecovered 계산
  5. updateDeductDailyForRecovery() → 즉시 소급
  → RP 배치에서 findTiRecoveryAmtForRiderOnDate()로 vr_rider_acct_daily 반영
```
