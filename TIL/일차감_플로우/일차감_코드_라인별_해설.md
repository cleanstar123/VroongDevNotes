## 1. `applyPreSettlementDeductionsAndRecovery()`
**파일**: `BaeminToVroongIfUseCase.java`  
**역할**: 매일 선정산 배치 실행 시 라이더 1명의 일차감·미수금 처리 전체를 담당

---

```java
private PreSettlementLedgerContext applyPreSettlementDeductionsAndRecovery(
    VrRiderAcctDailyEntity acctDaily) {
```
> 파라미터 `acctDaily`: 오늘 배치가 처리 중인 라이더의 일별 정산 엔티티.  
> 이 메서드 하나에서 일차감·미수금 계산을 모두 수행하고 결과를 `PreSettlementLedgerContext`로 반환한다.

---

```java
BigDecimal pool =
    acctDaily.getSettlementPoolBeforeRecovery() != null
        ? acctDaily.getSettlementPoolBeforeRecovery().max(BigDecimal.ZERO)
        : BigDecimal.ZERO;
```
> `settlementPoolBeforeRecovery`: 배달료에서 본사 수수료·협력사 수수료·보험료·세금을 모두 뺀 뒤 남은 금액.  
> 일차감을 차감할 수 있는 실질 재원(풀)이다.  
> `null`이면 0으로 처리, 음수가 나올 경우에도 `max(0)`으로 0으로 처리한다.

---

```java
List<SettlementDeductCandidate> candidates =
    acctDaily.getSettlementDeductCandidates() != null
        ? acctDaily.getSettlementDeductCandidates()
        : List.of();
```
> `settlementDeductCandidates`: 이 라이더에게 적용할 일차감 규칙 목록 (금액 내림차순 정렬된 상태).  
> `null`이면 빈 리스트로 처리해 NPE를 방지한다.

---

```java
BigDecimal prevUnpaidAmt =
    vrAccountMstQueryDslRepository.findLatestUnpaidAmtBySupplyIdAndRiderId(
        acctDaily.getSupplyId(), acctDaily.getRiderId());
```
> `vr_account_mst` 테이블에서 해당 라이더의 가장 최근 `UNPAID_AMT`를 조회한다.  
> 이전 배치에서 일차감을 다 못 뺀 경우 음수로 저장되어 있다. (예: `-5000` = 미수금 5,000원)  
> 미수금이 없으면 `null`이 반환된다.

---

### [Step 1] 이월 미수금 배달료 회수

```java
BigDecimal unpaidAbs =
    prevUnpaidAmt != null ? prevUnpaidAmt.negate().max(BigDecimal.ZERO) : BigDecimal.ZERO;
```
> `prevUnpaidAmt`는 음수이므로 `negate()`로 양수 변환한다.  
> 이후 계산에서 "미수금의 절댓값"으로 사용하기 위함이다.  
> `max(0)`은 혹시 양수가 들어왔을 경우의 방어 처리.

---

```java
BigDecimal unpaidRecoveryAmt = pool.min(unpaidAbs);
```
> 오늘 풀(배달료 가용 금액)과 이월 미수금 중 **작은 값**을 택한다.  
> - 풀 >= 미수금 → 미수금 전액 회수 가능  
> - 풀 < 미수금 → 풀 전부가 미수금 회수에 소진 (부분 회수)

---

```java
BigDecimal poolAfterUnpaid = pool.subtract(unpaidRecoveryAmt);
```
> 미수금 회수에 쓰인 금액을 풀에서 빼고 남은 금액.  
> 이후 일차감을 적용할 실제 가용 풀이 된다.

---

```java
if (unpaidRecoveryAmt.compareTo(BigDecimal.ZERO) > 0) {
    vrDeductDailyQueryDslRepository.updateDeductDailyForRecovery(
        acctDaily.getSupplyId(), acctDaily.getRiderId(), unpaidRecoveryAmt);
}
```
> 미수금 회수가 실제로 발생한 경우에만 `vr_deduct_daily` 소급 반영을 실행한다.  
> 회수액이 0이면 DB를 건드리지 않아 불필요한 쿼리를 방지한다.  
> `updateDeductDailyForRecovery()`는 과거 `vr_deduct_daily`의 `UNPAID_AMT`를 줄이고 `DEDUCT_AMT`를 늘려,  
> 주정산 `SUM(DEDUCT_AMT)`가 실제 징수액과 맞도록 소급 보정한다.

---

### [Step 2] 일차감 적용 (Largest Fits First)

```java
BigDecimal remaining = poolAfterUnpaid;
List<DeductApplicationResult> deductApplications = new ArrayList<>();
```
> 미수금 회수 후 남은 풀을 `remaining`으로 시작.  
> `deductApplications`: 각 일차감 규칙별 실제 적용액·유보액을 담을 결과 목록.

---

```java
for (SettlementDeductCandidate c : candidates) {
    BigDecimal targetAmt = c.amt() != null ? c.amt() : BigDecimal.ZERO;
```
> 일차감 후보 목록을 순서대로 순회한다 (금액 내림차순 = Largest Fits First).  
> `targetAmt`: 이 규칙이 요구하는 차감 금액. `null`이면 0으로 처리.

---

```java
    BigDecimal partial = remaining.min(targetAmt);
```
> 현재 남은 풀과 규칙 금액 중 작은 값 = 이 규칙에서 실제로 차감 가능한 금액.  
> 풀이 충분하면 `targetAmt` 전액, 부족하면 남은 풀만큼만.

---

```java
    deductApplications.add(
        new DeductApplicationResult(c.seqNo(), c.name(), partial, targetAmt.subtract(partial)));
```
> `DeductApplicationResult` 생성:  
> - `partial` → `actualAmt` (실제 차감된 금액)  
> - `targetAmt - partial` → `deferredAmt` (풀 부족으로 못 뺀 유보 금액)

---

```java
    remaining = remaining.subtract(partial);
}
```
> 실제 차감한 금액만큼 남은 풀을 줄인다.

---

```java
BigDecimal actualDeductVal =
    deductApplications.stream()
        .map(DeductApplicationResult::getActualAmt)
        .reduce(BigDecimal.ZERO, BigDecimal::add);
```
> 모든 규칙의 실제 차감액 합산 = 배달료 풀에서 실제로 빠진 일차감 총액.  
> 이 값이 `vr_rider_acct_daily.DEDUCT_VAL`의 1차 값이 된다.

---

```java
BigDecimal todayDeferred =
    deductApplications.stream()
        .map(DeductApplicationResult::getDeferredAmt)
        .reduce(BigDecimal.ZERO, BigDecimal::add);
```
> 모든 규칙의 유보액 합산 = 배달료 풀 부족으로 못 뺀 일차감 잔액.  
> 이 금액을 잔액에서 빼거나, 못 빼면 미수금으로 이월한다.

---

```java
BigDecimal totAcctVal = poolAfterUnpaid.subtract(actualDeductVal).max(BigDecimal.ZERO);
acctDaily.setTotAcctVal(totAcctVal);
```
> `TOT_ACCT_VAL`: 미수금 회수 후 남은 풀에서 실제 일차감을 뺀 값 = 라이더에게 지급되는 금액.  
> 음수 방지를 위해 `max(0)` 적용.

---

```java
BigDecimal totalCandidatesAmt =
    candidates.stream()
        .map(c -> c.amt() != null ? c.amt() : BigDecimal.ZERO)
        .reduce(BigDecimal.ZERO, BigDecimal::add);
acctDaily.setAcctVal(pool.subtract(totalCandidatesAmt));
```
> `ACCT_VAL`: 이론적 선지급 배달료 = 풀 - 일차감 규칙 총합.  
> 풀이 부족한 날은 음수가 되며, 주정산 `PRE_ACCT_VAL` 산출에 사용된다.

---

```java
acctDaily.setDeductVal(actualDeductVal);
acctDaily.setDeductApplications(deductApplications);
```
> `DEDUCT_VAL`에 배달료에서 실제 차감된 일차감 금액 기록.  
> `deductApplications`는 이후 `vr_deduct_daily` INSERT 시 규칙별 내역 기록에 사용된다.

### [Step 3] 잔액으로 유보분 처리 (Full-or-Nothing)

```java
BigDecimal currentBalAmt =
    vrAccountMstQueryDslRepository.findLatestBalAmtBySupplyIdAndRiderId(
        acctDaily.getSupplyId(), acctDaily.getRiderId());
BigDecimal availableBal =
    currentBalAmt != null ? currentBalAmt.max(BigDecimal.ZERO) : BigDecimal.ZERO;
```
> `vr_account_mst`에서 현재 라이더의 최신 잔액을 조회.  
> `null`이거나 음수면 0으로 처리 (사용 가능한 잔액은 최소 0).

---

```java
BigDecimal balanceDeductAmt =
    availableBal.compareTo(todayDeferred) >= 0 ? todayDeferred : BigDecimal.ZERO;
```
> **Full-or-Nothing 규칙**:  
> - 잔액 >= 유보분 → `balanceDeductAmt = todayDeferred` (잔액에서 전액 차감)  
> - 잔액 < 유보분 → `balanceDeductAmt = 0` (잔액에서 한 푼도 안 차감)  
>
> 부분 차감을 허용하지 않는 이유: 잔액을 일부만 빼면 다음 날 배달료·잔액으로 미수금을 회수할 경로가 막혀 미수금 해소가 더 어려워지기 때문.

---

```java
BigDecimal deferredAfterBalance = todayDeferred.subtract(balanceDeductAmt);
```
> 잔액 차감 후에도 남은 유보분 = 미수금으로 이월될 금액.  
> - 잔액에서 전액 차감됐으면 → `deferredAfterBalance = 0`  
> - 잔액이 부족해 차감 못 했으면 → `deferredAfterBalance = todayDeferred` (전액 이월)

---

```java
if (balanceDeductAmt.compareTo(BigDecimal.ZERO) > 0) {
    acctDaily.setDeductVal(acctDaily.getDeductVal().add(balanceDeductAmt));
}
```
> 잔액에서 실제로 차감이 발생한 경우, `DEDUCT_VAL`에 잔액 차감분을 추가로 더한다.  
> 최종 `DEDUCT_VAL` = 배달료에서 뺀 일차감 + 잔액에서 뺀 일차감.

---

### [Step 4] 잔액으로 남은 미수금 추가 회수

```java
BigDecimal remainingBalAfterDeduct = availableBal.subtract(balanceDeductAmt);
```
> 일차감 유보분 차감 후 남은 잔액.  
> 이 잔액으로 아직 배달료에서 다 못 회수한 이월 미수금을 추가 회수할 수 있다.

---

```java
BigDecimal remainingUnpaid = unpaidAbs.subtract(unpaidRecoveryAmt);
```
> 배달료로 회수한 미수금을 제외하고 아직 남은 미수금.  
> = 전체 미수금 - 배달료로 이미 회수한 금액.

---

```java
BigDecimal balRecoverAmt = remainingBalAfterDeduct.min(remainingUnpaid);
```
> 남은 잔액과 남은 미수금 중 작은 값 = 잔액으로 추가 회수할 수 있는 금액.  
> 배달료 회수와 달리 **부분 회수 허용** (풀이 아닌 잔액이라 Full-or-Nothing 적용 안 함).

---

```java
acctDaily.setUnpaidRecoveryAmt(unpaidRecoveryAmt);
acctDaily.setBalanceDeductAmt(balanceDeductAmt);
```
> `UNPAID_RECOVERY_AMT`: 배달료 풀에서 이월 미수금을 회수한 금액.  
> `BALANCE_DEDUCT_AMT`: 잔액에서 차감된 일차감 유보분.

---

```java
BigDecimal tiRecoverAmt =
    vrAccountMstQueryDslRepository.findTiRecoveryAmtForRiderOnDate(
        acctDaily.getSupplyId(), acctDaily.getRiderId(), acctDaily.getDeliveryDate());
acctDaily.setBalRecoverAmt(balRecoverAmt.add(tiRecoverAmt));
```
> 당일 TI(송금입금)로 해소된 미수금 금액을 별도 조회하여 `balRecoverAmt`에 합산.  
> TI는 실시간 처리 시 `vr_rider_acct_daily`를 직접 수정하지 않고, 배치 시점에 여기서 조회해 반영하는 방식.  
> `BAL_RECOVER_AMT` = 잔액 회수분 + TI 송금 회수분.

---

```java
BigDecimal depositRecoverAmt =
    vrAccountMstQueryDslRepository.findDepositRecoveryAmtForRiderOnDate(
        acctDaily.getSupplyId(), acctDaily.getRiderId(), acctDaily.getDeliveryDate());
acctDaily.setRecoverAmt(
    unpaidRecoveryAmt.add(balRecoverAmt).add(tiRecoverAmt).add(depositRecoverAmt));
```
> 당일 D(직접 입금)으로 해소된 미수금 금액 조회.  
> `RECOVER_AMT` = 배달료 회수 + 잔액 회수 + TI 송금 회수 + D 입금 회수 전체 합산.

---

```java
acctDaily.setSettlementPoolBeforeRecovery(null);
acctDaily.setSettlementDeductCandidates(null);
```
> 계산에 사용한 임시 필드를 `null`로 초기화.  
> 이 두 필드는 `@Transient`로 DB에 저장되지 않는 배치 전용 필드이며, 이후 불필요한 참조를 막기 위해 비운다.

---

### [Step 5] 신규 미수금 계산

```java
BigDecimal newUnpaidAmt =
    (prevUnpaidAmt != null ? prevUnpaidAmt : BigDecimal.ZERO)
        .add(unpaidRecoveryAmt)
        .add(balRecoverAmt)
        .subtract(deferredAfterBalance);
```
> 이번 배치 후 새로운 미수금 계산:  
> - `prevUnpaidAmt` (음수): 기존 이월 미수금  
> - `+ unpaidRecoveryAmt`: 배달료로 회수해서 미수금이 줄어든 만큼 (음수를 향해 +)  
> - `+ balRecoverAmt`: 잔액으로 회수해서 미수금이 줄어든 만큼  
> - `- deferredAfterBalance`: 새로 발생한 미수금 (차감이므로 음수 방향)

---

```java
if (newUnpaidAmt.compareTo(BigDecimal.ZERO) > 0) {
    newUnpaidAmt = BigDecimal.ZERO;
}
```
> 계산 결과가 양수면 0으로 강제한다.  
> 미수금은 항상 0 이하 (0 = 미수금 없음, 음수 = 미수금 존재).  
> 양수가 나왔다면 계산상 오차이므로 0으로 처리한다.

---

```java
return new PreSettlementLedgerContext(
    prevUnpaidAmt, currentBalAmt, unpaidRecoveryAmt,
    balanceDeductAmt, balRecoverAmt, newUnpaidAmt, depositRecoverAmt);
```

> 호출부(`BaeminToVroongIfUseCase`)에서 이 값을 `vr_account_mst`(원장) 저장에 사용한다.



> - `maxTranDay`가 있으면 그 날짜 이전 row만 대상 (배치의 `depositRecoverAmt` 처리 시 당일 신규 row 오염 방지)

## 3. `addRecoverAmtForDeposit()`
**파일**: `VrRiderAcctDailyQueryDslRepository.java`  
**역할**: 실시간 D(직접 입금) 처리 시 미수금 회수분을 이전 row에 임시 반영

---

```java

    String suppId, String riderId,
    BigDecimal amountRecovered, BigDecimal totalOutstanding,
    Long unpaidAcctDailySeqNo) {
```

> - `amountRecovered`: 이번 입금으로 실제 회수된 미수금 금액  
> - `totalOutstanding`: 입금 전 총 미수금 절댓값

## 4. `applyRecoveryToRow()`
**파일**: `VrRiderAcctDailyQueryDslRepository.java`  
**역할**: 특정 row에 RECOVER_AMT / BAL_RECOVER_AMT 반영

---

```java
BigDecimal currentRecover =
    target.getRecoverAmt() != null ? target.getRecoverAmt() : BigDecimal.ZERO;
BigDecimal currentBalRecover =
    target.getBalRecoverAmt() != null ? target.getBalRecoverAmt() : BigDecimal.ZERO;
BigDecimal currentBalDeduct =
    target.getBalanceDeductAmt() != null ? target.getBalanceDeductAmt() : BigDecimal.ZERO;
```
> 대상 row의 기존 값을 읽는다. `null`이면 0으로 처리.

---

```java
if (currentBalDeduct.compareTo(BigDecimal.ZERO) > 0) {
    BigDecimal outstanding = currentBalDeduct.subtract(currentBalRecover);
    toApply = amountToApply.min(outstanding);
    newBalDeduct = currentBalDeduct;
```
> `BALANCE_DEDUCT_AMT > 0` = 이 row에서 잔액 차감이 발생했던 경우.  
> `outstanding` = 아직 회수되지 않은 잔액 차감 잔여분 = `BALANCE_DEDUCT_AMT - BAL_RECOVER_AMT`.  
> 회수액은 이 잔여분을 초과할 수 없으므로 `min` 적용.  
> `newBalDeduct`: 기존 `BALANCE_DEDUCT_AMT` 유지.

---

```java
} else {
    // BALANCE_DEDUCT_AMT가 0 → Full-or-Nothing에 의해 잔액 차감이 발생하지 않은 경우
    toApply = amountToApply;
    newBalDeduct = BigDecimal.ZERO;
}
```
> `BALANCE_DEDUCT_AMT = 0` = 잔액 차감 없이 전액 미수금으로 이월된 경우.  
> 이 경우 입금액 전체를 회수로 처리한다.

---

```java
if (toApply.compareTo(BigDecimal.ZERO) <= 0) {
    return BigDecimal.ZERO;
}
```
> 실제 반영할 금액이 없으면 DB 업데이트 없이 종료.

---

```java
queryFactory.update(acctDaily)
    .set(acctDaily.recoverAmt,    currentRecover.add(toApply))
    .set(acctDaily.balRecoverAmt, currentBalRecover.add(toApply))
    .set(acctDaily.balanceDeductAmt, newBalDeduct)
    .set(acctDaily.updDate, now)
    .set(acctDaily.updUser, "SYSTEM")
    .where(acctDaily.seqNo.eq(target.getSeqNo()))
    .execute();
```
> `RECOVER_AMT += toApply`: 전체 회수 합계 누적  
> `BAL_RECOVER_AMT += toApply`: 잔액·입금 경로 회수 합계 누적  
> `BALANCE_DEDUCT_AMT = newBalDeduct`: 필요 시 갱신  
> `UPD_USER = "SYSTEM"`: 실시간 입금 처리 표시

## 5. `subtractDepositRecoveryFromPrevRow()`
**파일**: `VrRiderAcctDailyQueryDslRepository.java`  
**역할**: 익일 배치 실행 시 이전 row의 임시 반영분 차감 (2-phase 처리의 Phase 2)

---

```java
public void subtractDepositRecoveryFromPrevRow(
    String suppId, String riderId, String deliveryDate, BigDecimal depositRecoverAmt) {
    if (depositRecoverAmt == null || depositRecoverAmt.compareTo(BigDecimal.ZERO) <= 0) {
        return;
    }
```
> 차감할 금액이 없으면 즉시 종료. 방어 처리.  
> `deliveryDate`: 오늘 배치가 처리 중인 날짜 (= 입금이 발생했던 날).

---

```java
VrRiderAcctDailyEntity prevRow = queryFactory
    .selectFrom(acctDaily)
    .where(acctDaily.supplyId.eq(suppId)
           .and(acctDaily.riderId.eq(riderId))
           .and(acctDaily.deliveryDate.lt(deliveryDate)))
    .orderBy(acctDaily.deliveryDate.desc())
    .limit(1)
    .fetchOne();
```
> 오늘 배달일 이전의 가장 최근 row를 조회.  
> `addRecoverAmtForDeposit()`가 임시 반영해둔 바로 그 row다.

---

```java
BigDecimal toSubtract = depositRecoverAmt.min(currentBalRecover);
if (toSubtract.compareTo(BigDecimal.ZERO) <= 0) {
    return;
}
```
> 차감할 금액 = `depositRecoverAmt`와 기존 `BAL_RECOVER_AMT` 중 작은 값.  
> 임시 반영된 것보다 더 많이 차감하는 것을 방지.  
> 차감할 것이 없으면 종료.

---

```java
queryFactory.update(acctDaily)
    .set(acctDaily.recoverAmt,    currentRecover.subtract(toSubtract).max(BigDecimal.ZERO))
    .set(acctDaily.balRecoverAmt, currentBalRecover.subtract(toSubtract).max(BigDecimal.ZERO))
    .set(acctDaily.updDate, LocalDateTime.now())
    .set(acctDaily.updUser, "BATCH")
    .where(acctDaily.seqNo.eq(prevRow.getSeqNo()))
    .execute();
```
> `RECOVER_AMT -= toSubtract`: 이전 row의 임시 반영 회수분 제거  
> `BAL_RECOVER_AMT -= toSubtract`: 동일  
> `max(0)`: 음수 방지  
> `UPD_USER = "BATCH"`: 배치 처리 표시  
> 이 시점부터 해당 금액은 오늘 배치가 새로 만든 입금일 row에 정식 반영된다.

## 6. D타입 입금 처리에서 미수금 회수 판단


> 입금 후 유효 잔액 = 입금 전 유효 잔액 + 입금액.

> - `effectiveBal >= 0`: 미수금 완전 해소. 잔액 = effectiveBal, 미수금 = null  
> - `effectiveBal < 0`: 미수금 부분 해소. 잔액 = 0, 미수금 = effectiveBal (음수)

---

```java

```

---

```java
BigDecimal totalOutstanding = prevUnpaidAmt.negate();
BigDecimal amountRecovered;

    amountRecovered = totalOutstanding;        // 완전 해소

```
> 완전 해소: 미수금 전액 회수

> 예) 미수금 10,000, effectiveBal = -3,000 → 회수 = 10,000 + (-3,000) = 7,000
