# 일차감(deductVal) 로직 전체 정리

> 작성일: 2026-09-17  
> 프로젝트: vroong-backend  
> 관련 도메인: 선정산(PreSettlement), 차감(Deduct)

---

## 1. 개요

일차감이란 라이더의 **선정산 배달료에서 자동으로 차감되는 공제 항목**이다.  
마스터 테이블(`vr_deduct_mst`)에 등록된 규칙에 따라 매일 선정산 배치 실행 시 자동 적용된다.

### 핵심 원칙
- **부분 차감 허용**: 정산 가능 금액(pool)이 부족하면 가능한 만큼만 차감하고, 나머지는 미납금으로 다음 날 이월
- **우선순위**: 이월 미수금 회수 → 일차감 적용 순서
- **분리 관리**: HDC(본사 등록 차감)와 SDC(협력사 등록 차감)를 별도 추적

## 2. 관련 테이블 및 엔티티

| SUPP_ID         | VARCHAR(50)  | 협력사 ID                              |
| RIDER_ID        | VARCHAR(50)  | 라이더 ID (특정 라이더 지정 시)                |
| DEDUCT_TYPE     | VARCHAR(30)  | 공제 유형 (예: 보증금반환, 단말기비 등)            |

### 2.2 vr_rider_acct_daily (라이더 일별 정산)
선정산 배치 실행 결과를 날짜/라이더 단위로 저장.

| HDC_DEDUCT_VAL | 본사 등록 일차감 합계 (실제 차감액 + 이월 미수금 회수분) |

### 2.3 vr_deduct_daily (일차감 일별 상세)

| 컬럼            | 설명                       |

### 2.4 vr_account_mst (정산 원장)

## 3. 일차감 계산 공식

### 3.1 정액 공제 (CALC_TYPE = "1")
```
차감액 = vr_deduct_mst.DEDUCT_AMT  (고정 금액 그대로)
```

### 3.2 정률 공제 (CALC_TYPE = "2")
```
차감액 = 총배달료(totDeliveryAmt) × DEDUCT_RATE / 100  (HALF_UP 반올림)
```

### 3.3 조회 조건 (VrRiderAcctDailyQueryDslRepository.java:870)
정액/정률 공제 규칙을 불러올 때 아래 조건을 모두 만족해야 한다:
- `START_DAY <= deliveryDate <= END_DAY`
- `USE_YN = 'Y'`
- `DEDUCT_TARGET IN ('R', 'SRA')`
- `SUPP_ID = 해당 협력사`
- 계약 상태: `UNDER_CONTRACT` 또는 종료일 ≥ deliveryDate인 `TERMINATED_CONTRACT`
- 배달건수 조건:
  - 배달 1건 이상: `DAILY` 또는 `WORK_DAY` 타입 허용
  - 배달 0건: `DAILY` 타입만 허용

## 4. 선정산 배치 전체 흐름

### 4.1 흐름도
```
[1] 배송 데이터 집계
    └─ vr_delivery_fee_list.DELIVERY_AMT SUM → totDeliveryAmt
    └─ vr_delivery_list.FINISH_CNT MAX → totDeliveryCnt

[2] 정산 가능 금액(pool) 산출  ← calculateAcctDaily()
    배달료(deliveryVal)
      - 본사 수수료(brokerManageFee)
      - 협력사 수수료(partnerManageFee)
      - 보험료(riderEmpVal + riderAccidtVal + timeInsurVal)
      - 원천징수세(withholdTax)
    = baseAcctVal
    pool = max(baseAcctVal, 0)   ← 음수는 0으로

[3] 이월 미수금 회수             ← applyPreSettlementDeductionsAndRecovery()
    unpaidRecoveryAmt = min(pool, 이전 미수금)
    남은 pool -= unpaidRecoveryAmt

[4] 일차감 부분 차감 (Largest-Fits-First)
    후보 목록을 금액 내림차순 정렬 후 순서대로 적용:
    각 규칙별:
      actualAmt   = min(규칙 금액, 남은 pool)   ← 실제 차감액
      deferredAmt = 규칙 금액 - actualAmt        ← 미납금(다음 날 이월)
      남은 pool  -= actualAmt

[5] HDC / SDC 분리
    hdcDeductVal = HDC 규칙 actualAmt 합계 + HDC 이월미수금 회수분
    sdcDeductVal = SDC 규칙 actualAmt 합계 + SDC 이월미수금 회수분

[6] 최종 선지급배달료 산출
    preAcctVal = pool - (hdcActualAmt + sdcActualAmt)

[7] 저장
    ├─ vr_rider_acct_daily    : HDC_DEDUCT_VAL, SDC_DEDUCT_VAL, ACCT_VAL
    ├─ vr_deduct_daily        : 규칙별 실제 차감액 + 미납금
    └─ vr_account_mst         : RP / HDC / SDC 원장 기록
```

### 4.2 계산식 요약
```
pool          = max(배달료 - 수수료 - 보험료 - 세금, 0)
unpaidRecovery = min(pool, 이전미수금)
남은 pool     = pool - unpaidRecovery
actualAmt     = min(각 규칙금액, 남은 pool)   (규칙마다 순차 적용)
deferredAmt   = 규칙금액 - actualAmt
preAcctVal    = pool - Σ(actualAmt)
```

## 5. 미수금 이월 메커니즘

```
Day N:
  pool = 5,000원
  규칙 A = 8,000원 (정액)
  → actualAmt  = 5,000원  (pool 한도 내)
  → deferredAmt = 3,000원  (미납금, 내일 이월)
  → preAcctVal = 0원

Day N+1:
  pool = 10,000원
  이월 미수금 = 3,000원  ← 어제 deferredAmt
  → unpaidRecovery = 3,000원 (이월 미수금 먼저 회수)
  → 남은 pool = 7,000원
  → 규칙 A 다시 적용 (새 날짜 규칙 금액 기준)
  → preAcctVal = 7,000원 - 규칙금액
```

## 7. 주요 엣지 케이스

### 7.1 배달 0건인 날
- `DAILY` 타입 규칙만 적용 (WORK_DAY 타입은 스킵)
- pool = 0이므로 모든 일차감 → deferredAmt 100% 이월

### 7.2 계약 종료된 라이더
- `TERMINATED_CONTRACT` 상태이고 `종료일 >= deliveryDate`이면 규칙 적용 継続
- `batchUpdateEndDayByContEdDate()` 로 라이더 계약 종료일 변경 시 END_DAY 자동 업데이트

### 7.3 pool이 음수인 경우
- `baseAcctVal`이 음수이면 pool = 0으로 처리
- 모든 일차감이 deferredAmt로 이월됨
- `unpaidAmt`는 음수 형태로 vr_account_mst에 기록
