# 슬롯 관리 페이지 개발 v1

## 개요

부릉 라이더 대시보드에서 협력사별 슬롯 달성 목표를 유연하게 관리하기 위한 **슬롯 정책 관리 페이지**를 신규 개발하였다.
기존에는 공통코드 `SLOTINFO` (SLOT1~SLOT4)의 VAL1~VAL7 값이 모든 협력사에 동일하게 적용되었으나, 협력사마다 특성이 다르기 때문에 협력사별 맞춤 슬롯 정책이 필요하다는 고객사 요구가 발생하였다.

---

## 데이터베이스 구조

### 신규 테이블 3개

#### `vr_slot_policy` (정책 헤더)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| SEQ_NO | BIGINT PK | 자동 증가 |
| POLICY_NAME | VARCHAR(100) | 정책(그룹)명 (예: 안성A) |
| APPLY_START_DATE | VARCHAR(8) | 적용 시작일 (yyyyMMdd, 비어있으면 즉시 적용) |
| REQUIRED_SLOT_CNT | INT | 달성 필요 슬롯 수 |
| ACCEPTANCE_RATE | DECIMAL(5,2) | 수락률 조건 (%) |
| USE_YN | CHAR(1) | 사용 여부 |

> **제거된 컬럼**: `LIKE_PATTERN` (표준권역 기반 매칭으로 대체), `PRIORITY` (우선순위 기능 제거), `DASHBOARD_PLUS_YN` (미사용)

#### `vr_slot_policy_slot` (슬롯 상세)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| SEQ_NO | BIGINT PK | 자동 증가 |
| POLICY_SEQ_NO | BIGINT FK | 정책 헤더 참조 |
| SLOT_ORDER | INT | 슬롯 순서 (1부터, 개수 가변) |
| SLOT_NAME | VARCHAR(50) | 슬롯명 (예: 아침, 오후) |
| SLOT_START_TIME | VARCHAR(5) | 시작 시간 (HH:mm) |
| SLOT_END_TIME | VARCHAR(5) | 종료 시간 (HH:mm) |
| VAL1~VAL7 | VARCHAR(20) | 요일별 목표 건수 (1=월~7=일) |
| USE_YN | CHAR(1) | 사용 여부 (저장 시 항상 'Y' 고정, UI 노출 없음) |

#### `vr_slot_policy_area` (표준권역 매핑)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| SEQ_NO | BIGINT PK | 자동 증가 |
| POLICY_SEQ_NO | BIGINT FK | 정책 헤더 참조 |
| STANDARD_AREA | VARCHAR(100) | 표준권역명 |

## 기본 슬롯 체계 (SLOTINFO 공통코드)

슬롯 정책이 매칭되지 않는 협력사에는 기존 SLOTINFO 기본값이 적용된다.

| 슬롯 | 시간대 | 표시명 |
|------|--------|--------|
| SLOT1 | 06:00 ~ 12:59 | 아침점심피크 |
| SLOT2 | 13:00 ~ 16:59 | 오후논피크 |
| SLOT3 | 17:00 ~ 19:59 | 저녁피크 |
| SLOT4 | 20:00 ~ 02:59 | 심야논피크 |

SLOTINFO의 VAL1~VAL7은 요일별(1=월~7=일) **세트당 목표 건수**이다.
최종 목표 = `VAL × slotSetCnt` (협력사의 라이더 세트 수)

## 사용법

### 1. 정책 등록

1. 슬롯 관리 메뉴 진입 → **신규 등록** 버튼 클릭
2. 모달에서 다음 항목 입력:
   - **그룹명**: 필수. 정책 식별용 이름 (예: 안성A)
   - **적용 시작일**: 달력 피커(`type="date"`)로 선택. DB에는 yyyyMMdd 형식으로 저장. **비워두면 즉시 적용** (모달 내 안내 문구 표시)
   - **필수 달성 슬롯 수**: 설정 시 "하루에 N개 이상 슬롯 달성 여부"로 달성률 판정 방식 변경. 미설정(NULL) 시 슬롯별 개별 달성 방식 유지
   - **수락률**: 수락률 조건(%). 설정 시 협력사의 실제 수락률이 이 값 이상이어야 달성으로 인정
   - **사용 여부**: Y(사용) / N(미사용)
   - **표준권역**: `standardAreaApi.getStandardAreas()`로 등록된 권역 목록 로드 후 검색 필터 + 체크박스 멀티셀렉트로 선택. 비워두면 전체 협력사 기본 정책으로 동작
3. **슬롯 설정** 섹션에서 슬롯별 목표 건수 설정:
   - 슬롯명 입력, 시작/종료 시간은 `<select>` 드롭다운으로 선택 (시작: `HH:00` 고정, 종료: `HH:59` 고정, 05시·06시 선택 불가)
   - **슬롯 시간 겹침 불가**: 저장 시 겹치는 슬롯이 있으면 오류 표시 (자정 크로스 슬롯도 처리)
   - VAL1~VAL7: 요일별(월~일) 목표 건수 입력
   - **VAL을 0으로 입력** → 해당 슬롯은 달성 목표 없음 (대시보드에 수행물량만 표시)
   - **+ 슬롯 추가** 버튼으로 슬롯 행 추가 가능

### 2. 정책 목록 확인

- 목록 테이블의 **표준권역** 컬럼: 해당 정책에 매핑된 표준권역명 표시 (없으면 `-`)
- 목록 테이블의 **적용 시작일** 컬럼:
  - 날짜 미설정 → `즉시 적용` 표시
  - 날짜 설정 → `YYYY-MM-DD` 형식 표시
- 수정 버튼 클릭 시 기존 값이 모달에 로드됨

## 설정값에 따른 대시보드 결과

### 정책 매칭 로직

대시보드 조회 시 각 날짜마다 아래 순서로 협력사 목표치 결정:

```
1. 조회 날짜 기준 applyStartDate <= 날짜 이고 USE_YN='Y'인 정책 필터
2. 표준권역 매칭 필터
   - vr_slot_policy_area에 권역이 없으면 → 전체 협력사에 적용 (기본 정책)
   - vr_slot_policy_area에 권역이 있으면 → 협력사의 표준권역이 해당 집합에 포함되는 경우만 매칭
   - 협력사의 표준권역은 vr_supplier_info.DELIVERY_AREA에서 " (" 이전 문자열로 추출
3. 아래 우선순위로 1개 정책 선택
   applyStartDate DESC
   → 특정 권역 정책 > 전체 기본 정책 (권역 없음)
   → seqNo DESC (등록 순)
4. 매칭 정책 없으면 SLOTINFO 기본값 사용
5. 최종 목표 = VAL × slotSetCnt (정책 매칭/SLOTINFO 공통)
```

### 주요 케이스

| 상황 | 대시보드 목표값 |
|------|----------------|
| 정책 매칭 O (표준권역 일치) | 정책 VAL1~VAL7 × slotSetCnt |
| 정책 매칭 X | SLOTINFO VAL × slotSetCnt |
| 표준권역 미지정 정책 | 전체 협력사 기본 정책으로 적용 (특정 권역 정책이 있으면 그쪽 우선) |
| 협력사 deliveryArea 없음 | 전체 기본 정책(권역 없음)만 매칭, 특정 권역 정책 미적용 |
| applyStartDate 이전 날짜 조회 | 해당 날짜에 유효한 정책 적용 (날짜별 분기) |
| VAL = 0인 슬롯 | 대시보드에 수행물량만 표시 (예: `5`), 달성률 분모/분자에서 제외 |
| 해당 날짜 배달 이력 없음 | 실적 0, 적용 정책의 슬롯명/목표로 `0/목표` 표시 |
| `REQUIRED_SLOT_CNT` 설정 | 달성률 = 달성일 수 / 전체 조회일 수 (슬롯별 개별 카운트 방식 대신 하루 단위 미션 판정) |
| `REQUIRED_SLOT_CNT` 미설정 (NULL) | 기존 방식 유지. 슬롯 개별 달성 여부 누적 |
| `ACCEPTANCE_RATE` 설정 + 실제 수락률 미달 | `REQUIRED_SLOT_CNT` 설정된 경우, 슬롯 달성해도 해당일 전체 미달성으로 처리 |

### slotSetCnt 적용

- **SLOTINFO 기본값**: 목표 = `VAL × slotSetCnt`
- **신규 정책**: 목표 = `VAL × slotSetCnt` (동일)
- `slotSetCnt`는 협력사의 라이더 세트 수이며, 없거나 0 이하면 1로 처리

## 날짜별 정책 이력 관리

정책 교체 시 기존 정책을 삭제하지 않고 **새 정책을 applyStartDate와 함께 등록**한다.

```
예시:
- 정책A: 표준권역=[표준아산A], applyStartDate=20250101
- 정책B: 표준권역=[표준아산A], applyStartDate=20260801 (8월부터 목표 상향)

7월 31일 조회 → 정책A 적용
8월 01일 조회 → 정책B 적용 (applyStartDate가 더 최근)
```

이력이 자동으로 보존되어 과거 데이터를 조회해도 당시 정책이 정확히 반영된다.

## 8가지 요구사항 반영 현황

### ① 슬롯 정책 추가: "기본 슬롯" 외 별도 슬롯 정책 추가 기능

**반영 완료**

- `vr_slot_policy` 테이블 신규 설계 및 CRUD API 구현
- 프론트엔드 등록/수정/삭제 UI 구현
- 기존 SLOTINFO를 건드리지 않고 신규 정책이 우선 적용되는 구조

---

### ② 슬롯명 & 슬롯 시간 선택: 슬롯명과 슬롯 시간 개별 설정 가능

**반영 완료**

- `vr_slot_policy_slot`의 `SLOT_NAME`, `SLOT_START_TIME`, `SLOT_END_TIME` 컬럼에 개별 설정
- 모달 내 슬롯 테이블에서 각 행마다 슬롯명, 시작/종료 시간 입력 가능
- 시간은 `<select>` 드롭다운. `VALID_HOURS = [7,8,...,23,0,1,2,3,4]` (05시·06시 선택 불가). 시작은 분 `:00` 고정, 종료는 분 `:59` 고정
- **슬롯 시간 겹침 방지**: 저장 시 슬롯 간 시간대가 겹치면 오류. 자정 크로스 슬롯(예: 20:00~02:59)도 정확히 처리

---

### ③ 슬롯 미션 건수 개별 설정: 슬롯별 미션 건수(달성 필요 건수) 설정

**반영 완료**

- `vr_slot_policy_slot`의 `VAL1~VAL7`에 요일별(월~일) 목표 건수 저장
- 모달 내 슬롯 테이블의 각 컬럼(VAL1~VAL7)이 요일을 의미하며 숫자 입력
- 대시보드 조회 시 해당 날짜의 요일에 맞는 VAL 값이 목표로 사용됨

---

### ④ 슬롯 추가 기능: 현재 28개에서 추가 가능 기능 필요

**반영 완료**

- 모달 내 **+ 슬롯 추가** 버튼으로 슬롯 행을 동적으로 추가 가능
- 최소 1개 슬롯 유지 (삭제 버튼은 1개일 때 비활성화)
- 기본 등록 시 SLOTINFO 공통코드에서 SLOT1~SLOT4 기본값 자동 로드

---

### ⑤ "0건" 입력 슬롯 표기: 슬롯은 구분되어 있으나, 미션에 해당하지 않는 슬롯 별도 표기

**반영 완료**

- VAL1~VAL7을 모두 `0`으로 입력한 슬롯 → 대시보드에 **수행물량만 표시** (예: `5`)
- 이전 버전의 `—` 마커 방식에서 변경: 목표가 없어도 실제 수행된 건수는 보여준다
- 달성률 계산에서 0건 슬롯은 분모·분자 모두 제외 (`parseTargetCount` 반환값 0으로 자동 처리)

**백엔드 처리 위치**: `DashboardQueryDslRepository.buildSupplierPerformancesOptimized()`

```java
// 목표 0인 슬롯: 수행물량만 표시 (이전: ZERO_SLOT_TARGET = "-")
counts.add(target == 0 ? String.valueOf(achieved) : achieved + "/" + target);
slots.add(target == 0 ? String.valueOf(achieved) : formatRate(calculateRate(achieved, target)));
```

### ⑥ 달성 조건 추가: 달성 필요 슬롯 수, 수락률 추가

**반영 완료**

- `vr_slot_policy`에 `REQUIRED_SLOT_CNT`(필수 달성 슬롯 수), `ACCEPTANCE_RATE`(수락률) 컬럼 추가
- 모달 UI에서 입력/저장 가능
- 대시보드 슬롯 달성률 계산에 두 값 모두 실제 반영

**달성 판정 동작**:

| 설정 상태 | 달성률 계산 방식 |
|-----------|----------------|
| `REQUIRED_SLOT_CNT` 설정 (N > 0) | **미션 달성 모드**: 하루에 N개 이상 슬롯 달성 시 그날 "달성". 달성률 = 달성일 수 / 전체 조회일 수 |
| `REQUIRED_SLOT_CNT` 미설정 (NULL) | **기본 모드**: 슬롯 개별 달성 여부 누적. 달성률 = 달성 슬롯 수 / 전체 슬롯 수 |
| `ACCEPTANCE_RATE` 설정 | 수락률 조건 추가. 협력사 실제 수락률 < 설정값이면 슬롯을 달성해도 미달성으로 처리 |
| `ACCEPTANCE_RATE` 미설정 (NULL) | 수락률 조건 없음. 슬롯 달성 여부만으로 판정 |

두 조건은 AND 관계: `REQUIRED_SLOT_CNT` 설정 시 "N개 이상 달성 AND 수락률 >= 기준" 모두 충족해야 해당일 달성으로 인정.

**백엔드 처리 위치**:
- 전체 협력사 모드: `DashboardQueryDslRepository.recalculateSlotAchievementForActiveSuppliers()`
- 단일 협력사 모드: `DashboardQueryDslRepository.calculateSlotAchievementOptimized()`

### ⑦ 신규 슬롯 정책 적용일: 과거 데이터 오류 방지를 위해 정책 적용 일자 반영

**반영 완료**

- `vr_slot_policy.APPLY_START_DATE` 컬럼에 적용 시작일 저장 (yyyyMMdd)
- 대시보드 조회 시 **날짜별**로 `applyStartDate <= 해당날짜`인 정책 중 가장 최근 적용일 정책 선택
- 조회 기간 내 정책 변경이 있어도 날짜별로 다른 정책 자동 분기

**동작 원리**:
```
7/21~27 조회, 7/25 새 정책 등록 시
  → 7/21~24: 이전 정책 (applyStartDate 더 이전인 것)
  → 7/25~27: 새 정책 자동 적용
```

**정책 이력 관리**: 정책 수정 시 기존 정책을 삭제하지 않고 새 정책 등록. USE_YN=Y 유지로 과거 조회 시 이력 보존.

**UI**: 적용일 미입력 시 "비워두면 오늘부터 즉시 적용됩니다" 안내 표시. 목록에서는 "즉시 적용" 표기.

**백엔드 처리 위치**: `DashboardQueryDslRepository.resolveSupplierPolicyForDate()`

### ⑧ 신규 슬롯 반영, 표준 권역 선택: 선택 시(복수 가능) 기본 슬롯에서 해당 슬롯 제외

**반영 완료 (표준권역 기반 매칭으로 전환)**

- `vr_slot_policy_area` 테이블에 정책-표준권역 매핑 저장
- ~~LIKE_PATTERN 협력사명 매칭~~ → **표준권역 집합 포함 여부**로 협력사 매칭 방식 변경
- 협력사의 표준권역은 `vr_supplier_info.DELIVERY_AREA` 컬럼에서 `" ("` 이전 문자열로 추출 (예: `"표준안성A (안성A)"` → `"표준안성A"`)
- 표준권역이 비어 있는 정책 = 전체 협력사 기본 정책 (특정 권역 정책이 매칭되면 그쪽 우선)
- 표준권역 선택: 모달에서 검색 필터 + 체크박스 멀티셀렉트 (복수 선택 가능)
- 모달 목록 테이블: "LIKE 패턴" 컬럼 제거 → **"표준권역"** 컬럼으로 교체

## 주요 개발 포인트

### 표준권역 기반 협력사 매칭

기존 LIKE 패턴 → Java Regex 변환 방식에서, **표준권역 집합 포함 여부** 방식으로 전환하였다.

```java
// PolicyTargetsCache에 policyAreas 추가: policySeqNo → Set<standardArea>
Map<Long, Set<String>> policyAreas;

// 매칭 판정
Set<String> areas = cache.policyAreas.get(pSeqNo);
if (areas == null || areas.isEmpty()) return true;   // 권역 없음 → 전체 적용
if (suppStandardArea == null) return false;           // 협력사 권역 없음 → 전체 기본만 적용
return areas.contains(suppStandardArea);
```

협력사 표준권역 로드는 `buildSuppStandardAreaMap()`:
```java
// vrSupplierInfoRepository.findBySuppIdIn(suppIds) 호출
// deliveryArea에서 " (" 이전 문자열 추출
String area = deliveryArea.indexOf(" (") >= 0
    ? deliveryArea.substring(0, deliveryArea.indexOf(" (")).trim()
    : deliveryArea.trim();
```

### slotSetCnt 처리

정책 매칭 여부와 관계없이 목표는 동일하게 `VAL × slotSetCnt`로 계산한다.

long target = entry.getValue().getOrDefault(dayOfWeek, 0L) * slotSetCnt;

// SLOTINFO 폴백 시

### 날짜별 정책 캐싱 전략

조회 기간의 `toDate` 이전에 시작된 모든 정책을 한 번에 로드한 뒤, 각 날짜·협력사 조합마다 스트림 필터링으로 적합한 정책을 결정한다.

DB 쿼리는 1회, Java 레벨에서 날짜별 분기 처리 → N+1 문제 없음.

`PolicyTargetsCache`는 정책별 슬롯 목표치·시간대·슬롯명·`REQUIRED_SLOT_CNT`·`ACCEPTANCE_RATE` 외에 **`policyAreas` (표준권역 집합)**도 함께 캐싱하여 달성률 계산과 협력사 매칭 시 별도 조회 없이 사용한다.

### 달성률 이중 모드 계산

정책에 `REQUIRED_SLOT_CNT`가 설정되어 있는지 여부로 계산 방식이 분기된다.

```
REQUIRED_SLOT_CNT = NULL (미설정)
  → 기본 모드: 슬롯별 개별 달성 누적
     달성률 = Σ(달성 슬롯) / Σ(유효 슬롯)

REQUIRED_SLOT_CNT = N (설정)
  → 미션 달성 모드: 하루 단위 판정
     조건 1: 하루 달성 슬롯 수 >= N
     조건 2: (ACCEPTANCE_RATE 설정 시) 협력사 수락률 >= 기준
     두 조건 모두 충족한 날 = "달성일"
     달성률 = 달성일 수 / 전체 조회일 수
```

동일 조회 내 협력사마다 다른 정책(모드)이 적용될 수 있으며, 두 모드의 결과는 수치상 같은 비율(0~100%)로 표현되므로 전체 달성률에 합산 가능하다.

### 슬롯 시간 겹침 방지 (프론트엔드)

자정을 크로스하는 슬롯(예: 20:00~02:59)도 정확히 처리한다.

```typescript
// 자정 크로스 슬롯을 [start, 1440) + [0, end+1) 두 구간으로 분리
function slotIntervals(startMin: number, endMin: number): [number, number][] {
    if (endMin >= startMin) return [[startMin, endMin + 1]];
    return [[startMin, 1440], [0, endMin + 1]];
}
// 모든 슬롯 구간 쌍을 비교하여 겹치는 쌍이 있으면 저장 차단
```
