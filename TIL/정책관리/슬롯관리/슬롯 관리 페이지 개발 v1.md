# 슬롯 관리 페이지 개발 v1

## 개요

부릉 라이더 대시보드에서 협력사별 슬롯 달성 목표를 유연하게 관리하기 위한 **슬롯 정책 관리 페이지**를 신규 개발하였다.
기존에는 공통코드 `SLOTINFO` (SLOT1~SLOT4)의 VAL1~VAL7 값이 모든 협력사에 동일하게 적용되었으나, 협력사마다 특성이 다르기 때문에 협력사별 맞춤 슬롯 정책이 필요하다는 고객사 요구가 발생하였다.

## 데이터베이스 구조

### 신규 테이블 4개

#### `vr_slot_policy` (정책 헤더)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| SEQ_NO | BIGINT PK | 자동 증가 |
| POLICY_NAME | VARCHAR(100) | 정책(그룹)명 (예: 안성A) |
| APPLY_START_DATE | VARCHAR(8) | 적용 시작일 (yyyyMMdd, 비어있으면 즉시 적용) |
| REQUIRED_SLOT_CNT | INT | 달성 필요 슬롯 수 |
| ACCEPTANCE_RATE | DECIMAL(5,2) | 수락률 조건 (%) |
| USE_YN | CHAR(1) | 사용 여부 |

> **제거된 컬럼**: `LIKE_PATTERN` (표준권역 기반 매칭으로 대체), `PRIORITY` (우선순위 기능 제거), `DASHBOARD_PLUS_YN` (미사용)

#### `vr_slot_policy_slot` (슬롯 상세)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| SEQ_NO | BIGINT PK | 자동 증가 |
| POLICY_SEQ_NO | BIGINT FK | 정책 헤더 참조 |
| SLOT_ORDER | INT | 슬롯 순서 (1부터, 개수 가변) |
| SLOT_NAME | VARCHAR(50) | 슬롯명 (예: 아침, 아침점심피크) |
| USE_YN | CHAR(1) | 사용 여부 (저장 시 항상 'Y' 고정, UI 노출 없음) |

> **제거된 컬럼**: `SLOT_START_TIME`, `SLOT_END_TIME`, `VAL1~VAL7` → 요일별 별도 테이블(`vr_slot_policy_slot_day`)로 분리

#### `vr_slot_policy_slot_day` (슬롯 요일별 시간/목표) ← **신규**

| 컬럼 | 타입 | 설명 |
|------|------|------|
| SEQ_NO | BIGINT PK | 자동 증가 |
| SLOT_SEQ_NO | BIGINT FK | 슬롯 상세 참조 |
| DAY_OF_WEEK | INT | 요일 (1=월, 2=화, ..., 7=일) |
| START_TIME | VARCHAR(5) | 시작 시간 (HH:MM) |
| END_TIME | VARCHAR(5) | 종료 시간 (HH:MM) |
| TARGET_CNT | VARCHAR(20) | 목표 건수 |

슬롯 하나당 최대 7개의 day 레코드(요일별)를 가질 수 있어, **요일마다 다른 시간대와 목표 건수 설정**이 가능하다.

#### `vr_slot_policy_area` (표준권역 매핑)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| SEQ_NO | BIGINT PK | 자동 증가 |
| POLICY_SEQ_NO | BIGINT FK | 정책 헤더 참조 |
| STANDARD_AREA | VARCHAR(100) | 표준권역명 |

## 기본 슬롯 체계

### SLOTINFO 공통코드 (정책 미적용 협력사 폴백)

슬롯 정책이 매칭되지 않는 협력사에는 기존 SLOTINFO 기본값이 적용된다.

| 슬롯 | 시간대 | 표시명 |
|------|--------|--------|
| SLOT1 | 06:00 ~ 12:59 | 아침점심피크 |
| SLOT2 | 13:00 ~ 16:59 | 오후논피크 |
| SLOT3 | 17:00 ~ 19:59 | 저녁피크 |
| SLOT4 | 20:00 ~ 02:59 | 심야논피크 |

SLOTINFO의 VAL1~VAL7은 요일별(1=월~7=일) **세트당 목표 건수**이다.
최종 목표 = `VAL × slotSetCnt` (협력사의 라이더 세트 수)

### 신규 등록 시 기본 슬롯 6개

신규 정책 등록 모달을 열면 SLOTINFO 기본값을 참조하여 아래 6개 슬롯이 자동으로 세팅된다.
평일(1~5)과 주말(6~7)의 시간대가 일부 다르다.

| 슬롯명 | 평일 시간 | 주말 시간 | 목표 건수 |
|--------|-----------|-----------|-----------|
| 아침 | 06:00 ~ 08:59 | 06:00 ~ 08:59 | 빈값 (직접 입력) |
| 아침점심피크 | 09:00 ~ 12:59 | 09:00 ~ 13:59 | SLOT1 VAL1~VAL7 |
| 오후논피크 | 13:00 ~ 16:59 | 14:00 ~ 16:59 | SLOT2 VAL1~VAL7 |
| 저녁피크 | 17:00 ~ 19:59 | 17:00 ~ 19:59 | SLOT3 VAL1~VAL7 |
| 심야논피크 | 20:00 ~ 23:59 | 20:00 ~ 23:59 | SLOT4 VAL1~VAL7 |
| 심야 | 00:00 ~ 05:59 | 00:00 ~ 05:59 | 0 (목표 없음) |

> 아침과 심야 슬롯은 SLOTINFO에 대응 코드가 없으므로 건수는 빈값/0으로 초기화된다.

## 사용법

### 1. 정책 등록

1. 슬롯 관리 메뉴 진입 → **+ 정책 추가** 버튼 클릭
2. 모달에서 다음 항목 입력:
   - **그룹명**: 필수. 정책 식별용 이름 (예: 안성A)
   - **적용 시작일**: 달력 피커(`type="date"`)로 선택. DB에는 yyyyMMdd 형식으로 저장. **비워두면 즉시 적용** (모달 내 안내 문구 표시)
   - **사용 여부**: Y(사용) / N(미사용)
   - **표준권역**: 검색 필터 + 체크박스 멀티셀렉트로 선택
     - **기본 체크박스**: 최상단에 위치. 체크 시 표준권역을 비워두고 SLOTINFO 기본값으로 슬롯 초기화 → 모든 협력사에 적용되는 기본 정책으로 저장
     - 특정 권역 선택 시: 해당 권역 협력사에만 적용
3. **슬롯 설정** 섹션에서 슬롯별 요일별 목표 건수 설정:
   - 슬롯명 입력 (필수)
   - 각 요일(월~일) 컬럼별로 시작/종료 시간 `<select>` 드롭다운과 목표 건수 `<input>` 입력
   - 시간 선택 범위: `06:00 ~ 05:59` (배민 영업일 기준 전 시간대 선택 가능, 시작은 분 `:00` 고정, 종료는 분 `:59` 고정)
   - **슬롯 시간 겹침 불가**: 요일별로 겹치는 슬롯이 있으면 저장 차단 (자정 크로스 슬롯도 처리)
   - **+ 슬롯 추가** 버튼으로 슬롯 행 추가 가능

### 2. 정책 목록 확인

- 목록 테이블의 **표준권역** 컬럼:
  - 표준권역 없는 기본 정책 → `모든 협력사 적용` (초록색 텍스트) 표시
  - 특정 권역 정책 → 매핑된 표준권역명 표시
- **기본 정책**은 항상 테이블 최상단에 고정되며, 그룹명 옆에 `기본` 뱃지와 연초록 행 배경으로 구분됨
- 목록 테이블의 **적용 시작일** 컬럼:
  - 날짜 미설정 → `즉시 적용` 표시
  - 날짜 설정 → `YYYY-MM-DD` 형식 표시
- 수정 버튼 클릭 시 기존 값이 모달에 로드됨 (표준권역 없는 정책은 "기본" 체크박스가 자동으로 체크됨)

### 3. 전체 협력사 적용(기본) 정책 제약

- 표준권역이 없는 기본 정책은 **하나만 등록 가능**
  - 모달에서 "기본" 체크박스 클릭 시: 이미 기본 정책이 존재하면 alert로 차단
  - 저장 시: 중복 기본 정책 시도 시 toast 에러 메시지 표시

## 설정값에 따른 대시보드 결과

### 정책 매칭 로직

대시보드 조회 시 각 날짜마다 아래 순서로 협력사 목표치 결정:

```
1. 조회 날짜 기준 applyStartDate <= 날짜 이고 USE_YN='Y'인 정책 필터
2. 표준권역 매칭 필터
   - vr_slot_policy_area에 권역이 없으면 → 전체 협력사에 적용 (기본 정책)
   - vr_slot_policy_area에 권역이 있으면 → 협력사의 표준권역이 해당 집합에 포함되는 경우만 매칭
   - 협력사의 표준권역은 vr_supplier_info.DELIVERY_AREA에서 " (" 이전 문자열로 추출
3. 아래 우선순위로 1개 정책 선택
   ① 특정 권역 정책 > 전체 기본 정책 (권역 없음) — 항상 최우선
   ② applyStartDate DESC (더 최근 정책 우선)
   ③ seqNo DESC (등록 순 타이브레이커)
4. 매칭 정책 없으면 SLOTINFO 기본값 사용
5. 최종 목표 = VAL × slotSetCnt (정책 매칭/SLOTINFO 공통)
```

> **버그 수정 이력**: 기존에는 날짜를 1순위로 비교하여, 기본 정책의 applyStartDate가 특정 권역 정책보다 늦으면 기본 정책이 우선 적용되는 문제가 있었다. 권역 특정성을 1순위로 올려 수정하였다.

### 주요 케이스

| 상황 | 대시보드 목표값 |
|------|----------------|
| 정책 매칭 O (표준권역 일치) | 정책 요일별 목표 건수 × slotSetCnt |
| 정책 매칭 X | SLOTINFO VAL × slotSetCnt |
| 표준권역 미지정 정책 (기본) | 전체 협력사 기본 정책으로 적용 (특정 권역 정책이 있으면 그쪽 우선) |
| 협력사 deliveryArea 없음 | 전체 기본 정책(권역 없음)만 매칭, 특정 권역 정책 미적용 |
| applyStartDate 이전 날짜 조회 | 해당 날짜에 유효한 정책 적용 (날짜별 분기) |
| VAL = 0인 슬롯 | 대시보드에 수행물량만 표시 (예: `5`), 달성률 분모/분자에서 제외 |
| 해당 날짜 배달 이력 없음 | 실적 0, 적용 정책의 슬롯명/목표로 `0/목표` 표시 |
| `REQUIRED_SLOT_CNT` 설정 | 달성률 = 달성일 수 / 전체 조회일 수 (슬롯별 개별 카운트 방식 대신 하루 단위 미션 판정) |
| `REQUIRED_SLOT_CNT` 미설정 (NULL) | 기존 방식 유지. 슬롯 개별 달성 여부 누적 |
| `ACCEPTANCE_RATE` 설정 + 실제 수락률 미달 | `REQUIRED_SLOT_CNT` 설정된 경우, 슬롯 달성해도 해당일 전체 미달성으로 처리 |

### slotSetCnt 적용

- **SLOTINFO 기본값**: 목표 = `VAL × slotSetCnt`
- **신규 정책**: 목표 = `요일별 targetCnt × slotSetCnt` (동일 구조)
- `slotSetCnt`는 협력사의 라이더 세트 수이며, 없거나 0 이하면 1로 처리

## 날짜별 정책 이력 관리

정책 교체 시 기존 정책을 삭제하지 않고 **새 정책을 applyStartDate와 함께 등록**한다.

```
예시:
- 정책A: 표준권역=[표준아산A], applyStartDate=20250101
- 정책B: 표준권역=[표준아산A], applyStartDate=20260801 (8월부터 목표 상향)

7월 31일 조회 → 정책A 적용
8월 01일 조회 → 정책B 적용 (applyStartDate가 더 최근)
```

이력이 자동으로 보존되어 과거 데이터를 조회해도 당시 정책이 정확히 반영된다.

## 8가지 요구사항 반영 현황

### ① 슬롯 정책 추가: "기본 슬롯" 외 별도 슬롯 정책 추가 기능

**반영 완료**

- `vr_slot_policy` 테이블 신규 설계 및 CRUD API 구현
- 프론트엔드 등록/수정/삭제 UI 구현
- 기존 SLOTINFO를 건드리지 않고 신규 정책이 우선 적용되는 구조

---

### ② 슬롯명 & 슬롯 시간 선택: 슬롯명과 슬롯 시간 개별 설정 가능

**반영 완료 (요일별 개별 시간 설정으로 확장)**

- `vr_slot_policy_slot`의 `SLOT_NAME`에 슬롯명 설정
- 시간/목표는 `vr_slot_policy_slot_day` 테이블에 요일별로 저장 (기존 단일 시작/종료 컬럼에서 변경)
- 모달 내 슬롯 테이블: 슬롯명 1컬럼 + 요일(월~일) × (시작/종료/건수) 3컬럼 = 총 22컬럼
- 시간은 `<select>` 드롭다운. `VALID_HOURS = [6, 7, ..., 23, 0, 1, 2, 3, 4, 5]` (배민 영업일 기준 06:00~05:59 전 시간대 선택 가능). 시작은 분 `:00` 고정, 종료는 분 `:59` 고정
- **슬롯 시간 겹침 방지**: 저장 시 요일별로 슬롯 간 시간대가 겹치면 오류. 자정 크로스 슬롯도 정확히 처리

---

### ③ 슬롯 미션 건수 개별 설정: 슬롯별 미션 건수(달성 필요 건수) 설정

**반영 완료 (요일별 개별 설정으로 확장)**

- `vr_slot_policy_slot_day`의 `TARGET_CNT`에 요일별 목표 건수 저장 (기존 `VAL1~VAL7` 컬럼 방식에서 변경)
- 모달 내 슬롯 테이블의 각 요일 컬럼에서 건수를 직접 숫자 입력
- 대시보드 조회 시 해당 날짜의 요일(dayOfWeek)에 맞는 targetCnt 값이 목표로 사용됨

---

### ④ 슬롯 추가 기능: 현재 4개에서 추가 가능 기능 필요

**반영 완료**

- 모달 내 **+ 슬롯 추가** 버튼으로 슬롯 행을 동적으로 추가 가능
- 최소 1개 슬롯 유지 (삭제 버튼은 1개일 때 비활성화)
- 신규 등록 시 기본 6개 슬롯 자동 세팅 (아침/아침점심피크/오후논피크/저녁피크/심야논피크/심야)
- SLOTINFO 공통코드(SLOT1~SLOT4)의 요일별 건수가 아침점심피크~심야논피크에 자동 적용됨

---

### ⑤ "0건" 입력 슬롯 표기: 슬롯은 구분되어 있으나, 미션에 해당하지 않는 슬롯 별도 표기

**반영 완료**

- `TARGET_CNT`를 모두 `0`으로 입력한 슬롯 → 대시보드에 **수행물량만 표시** (예: `5`)

**백엔드 처리 위치**: `DashboardQueryDslRepository.buildSupplierPerformancesOptimized()`

```java
// 목표 0인 슬롯: 수행물량만 표시
counts.add(target == 0 ? String.valueOf(achieved) : achieved + "/" + target);
slots.add(target == 0 ? String.valueOf(achieved) : formatRate(calculateRate(achieved, target)));
```

### ⑥ 달성 조건 추가: 달성 필요 슬롯 수, 수락률 추가

**반영 완료**

- `vr_slot_policy`에 `REQUIRED_SLOT_CNT`(필수 달성 슬롯 수), `ACCEPTANCE_RATE`(수락률) 컬럼 추가
- 모달 UI에서 입력/저장 가능 (현재 UI에서는 숨김 처리, 백엔드는 정상 반영)
- 대시보드 슬롯 달성률 계산에 두 값 모두 실제 반영

**달성 판정 동작**:

| 설정 상태 | 달성률 계산 방식 |
|-----------|----------------|
| `REQUIRED_SLOT_CNT` 설정 (N > 0) | **미션 달성 모드**: 하루에 N개 이상 슬롯 달성 시 그날 "달성". 달성률 = 달성일 수 / 전체 조회일 수 |
| `REQUIRED_SLOT_CNT` 미설정 (NULL) | **기본 모드**: 슬롯 개별 달성 여부 누적. 달성률 = 달성 슬롯 수 / 전체 슬롯 수 |
| `ACCEPTANCE_RATE` 설정 | 수락률 조건 추가. 협력사 실제 수락률 < 설정값이면 슬롯을 달성해도 미달성으로 처리 |
| `ACCEPTANCE_RATE` 미설정 (NULL) | 수락률 조건 없음. 슬롯 달성 여부만으로 판정 |

두 조건은 AND 관계: `REQUIRED_SLOT_CNT` 설정 시 "N개 이상 달성 AND 수락률 >= 기준" 모두 충족해야 해당일 달성으로 인정.

**백엔드 처리 위치**:
- 전체 협력사 모드: `DashboardQueryDslRepository.recalculateSlotAchievementForActiveSuppliers()`
- 단일 협력사 모드: `DashboardQueryDslRepository.calculateSlotAchievementOptimized()`

## 주요 개발 포인트

### 요일별 슬롯 시간/목표 분리 (`vr_slot_policy_slot_day`)

기존에는 슬롯 하나에 `SLOT_START_TIME`, `SLOT_END_TIME`(단일), `VAL1~VAL7`(요일별 건수)이 같은 행에 있었다. 즉 시간대는 요일에 무관하게 동일해야 했다.

신규 구조에서는 슬롯당 day 레코드를 별도 테이블에 저장하여 **요일별로 다른 시간대와 목표** 설정이 가능하다.

```
vr_slot_policy_slot (아침점심피크, SLOT_ORDER=2)
  ↳ vr_slot_policy_slot_day: 월~금 09:00~12:59 / 토~일 09:00~13:59
```

**백엔드 저장 흐름** (`SlotPolicyUseCase.saveSlotPolicy`):
1. 슬롯 엔티티(`VrSlotPolicySlotEntity`) 저장 → `seqNo` 확보
2. 해당 `seqNo`로 day 레코드(`VrSlotPolicySlotDayEntity`) 저장

**백엔드 캐시 로드 흐름** (`DashboardQueryDslRepository.loadActivePoliciesCache`):
1. 정책 → 슬롯 → `slotSeqNos` 수집
2. `findBySlotSeqNoIn(slotSeqNos)` 단일 배치 조회
3. `groupingBy(slotSeqNo)` 로 슬롯별 day 맵 구성
4. `policySlotHours`: `Map<Long, Map<String, Map<Integer, int[]>>>` (policySeqNo → slotCode → dayOfWeek → [startHour, endHour])

### 정책 매칭 우선순위 수정

기존 코드는 `resolveSupplierPolicyForDate`에서 날짜를 1순위로 비교하여, 기본 정책의 `applyStartDate`가 특정 권역 정책보다 늦으면 기본 정책이 우선 선택되는 버그가 있었다.

```java
// 수정 전 (버그): 날짜 → 권역 특정성 → seqNo
// 수정 후 (정상): 권역 특정성 → 날짜 → seqNo

.max(
    java.util.Comparator.comparingInt(
            (VrSlotPolicyEntity p) -> {
              Long pSeqNo = p.getSeqNo() != null ? p.getSeqNo().longValue() : 0L;
              java.util.Set<String> areas = cache.policyAreas.get(pSeqNo);
              return (areas != null && !areas.isEmpty()) ? 1 : 0; // 특정 권역=1, 기본=0
            })
        .thenComparing(p -> {
              String d = p.getApplyStartDate();
              return (d == null || d.isBlank()) ? "" : d;
            })
        .thenComparingLong(p -> p.getSeqNo() != null ? p.getSeqNo().longValue() : 0L));
```

### 표준권역 기반 협력사 매칭

기존 LIKE 패턴 → Java Regex 변환 방식에서, **표준권역 집합 포함 여부** 방식으로 전환하였다.

```java

// 매칭 판정

if (areas == null || areas.isEmpty()) return true;   // 권역 없음 → 전체 적용 (기본 정책)
if (suppStandardArea == null) return false;           // 협력사 권역 없음 → 전체 기본만 적용
return areas.contains(suppStandardArea);
```

### 날짜별 정책 캐싱 전략

조회 기간의 `toDate` 이전에 시작된 모든 정책을 한 번에 로드한 뒤, 각 날짜·협력사 조합마다 스트림 필터링으로 적합한 정책을 결정한다.

DB 쿼리는 1회, Java 레벨에서 날짜별 분기 처리 → N+1 문제 없음.

`PolicyTargetsCache`는 정책별 슬롯 목표치·시간대·슬롯명·`REQUIRED_SLOT_CNT`·`ACCEPTANCE_RATE`·**`policyAreas`(표준권역 집합)**를 함께 캐싱하여 달성률 계산과 협력사 매칭 시 별도 조회 없이 사용한다.

### 달성률 이중 모드 계산

정책에 `REQUIRED_SLOT_CNT`가 설정되어 있는지 여부로 계산 방식이 분기된다.

```
REQUIRED_SLOT_CNT = NULL (미설정)
  → 기본 모드: 슬롯별 개별 달성 누적
     달성률 = Σ(달성 슬롯) / Σ(유효 슬롯)

REQUIRED_SLOT_CNT = N (설정)
  → 미션 달성 모드: 하루 단위 판정
     조건 1: 하루 달성 슬롯 수 >= N
     조건 2: (ACCEPTANCE_RATE 설정 시) 협력사 수락률 >= 기준
     두 조건 모두 충족한 날 = "달성일"
     달성률 = 달성일 수 / 전체 조회일 수
```

동일 조회 내 협력사마다 다른 정책(모드)이 적용될 수 있으며, 두 모드의 결과는 수치상 같은 비율(0~100%)로 표현되므로 전체 달성률에 합산 가능하다.

### 슬롯 시간 겹침 방지 (프론트엔드)

요일별로 각각 겹침 검사를 수행한다. 자정을 크로스하는 슬롯(예: 00:00~05:59)도 정확히 처리한다.

```typescript
function slotsHaveOverlap(slots: { days: SlotDayItemForm[] }[]): boolean {
    for (let dow = 1; dow <= 7; dow++) {
        // 해당 요일의 모든 슬롯 구간 수집
        const segs: [number, number, number][] = [];
        for (let i = 0; i < slots.length; i++) {
            const day = slots[i].days.find(d => d.dayOfWeek === dow);
            if (!day) continue;
            const s = parseMinutes(day.startTime);
            const e = parseMinutes(day.endTime);
            if (s === null || e === null) continue;
            for (const [is, ie] of slotIntervals(s, e)) segs.push([is, ie, i]);
        }
        // 요일 내 슬롯 구간 쌍을 비교하여 겹치면 true 반환
        for (let i = 0; i < segs.length; i++)
            for (let j = i + 1; j < segs.length; j++)
                if (segs[i][2] !== segs[j][2] && segs[i][0] < segs[j][1] && segs[j][0] < segs[i][1])
                    return true;
    }
    return false;
}

// 자정 크로스 슬롯을 [start, 1440) + [0, end+1) 두 구간으로 분리
function slotIntervals(startMin: number, endMin: number): [number, number][] {
    if (endMin >= startMin) return [[startMin, endMin + 1]];
    return [[startMin, 1440], [0, endMin + 1]];
}
```
