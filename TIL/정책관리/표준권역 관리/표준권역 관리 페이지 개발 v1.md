# 표준권역 관리 페이지 개발 v1

작성일: 2026-07-30

---

## 개요

슬롯 정책을 특정 지역 단위로 묶어 관리하기 위한 "표준권역" 기능.  
협력사(SUPP_ID)를 권역 단위로 그룹핑하고, 슬롯 정책 등록 시 자유 입력 대신 등록된 권역을 선택하게 한다.

자동 등록 기능: 협력사명(SUPP_NAME)에서 "부릉" 이전 문자열을 추출해 권역명으로 사용하며, 협력사 매핑까지 자동 생성한다.

---

## DB 테이블

```sql
-- 표준권역 마스터
CREATE TABLE `vr_standard_area` (
  `SEQ_NO`     bigint       NOT NULL AUTO_INCREMENT,
  `AREA_NAME`  varchar(100) NOT NULL COMMENT '표준권역명',
  `USE_YN`     char(1)      NOT NULL DEFAULT 'Y',
  `INS_DATE`   datetime     DEFAULT NULL,
  `INS_USER`   varchar(50)  DEFAULT NULL,
  `UPD_DATE`   datetime     DEFAULT NULL,
  `UPD_USER`   varchar(50)  DEFAULT NULL,
  PRIMARY KEY (`SEQ_NO`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='표준권역 관리';

-- 권역-협력사 매핑 (N:M 정규화)
CREATE TABLE `vr_standard_area_supplier` (
  `SEQ_NO`      bigint      NOT NULL AUTO_INCREMENT,
  `AREA_SEQ_NO` bigint      NOT NULL COMMENT 'vr_standard_area.SEQ_NO',
  `SUPP_ID`     varchar(50) NOT NULL COMMENT '협력사 ID',
  `INS_DATE`    datetime    DEFAULT NULL,
  `INS_USER`    varchar(50) DEFAULT NULL,
  PRIMARY KEY (`SEQ_NO`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='표준권역-협력사 매핑';
```

### 핵심 컬럼

| 컬럼 | 설명 |
|------|------|
| `vr_standard_area.AREA_NAME` | 표준권역명 (예: 안성A, 경기파주A) |
| `vr_standard_area.USE_YN` | 사용 여부 — N이면 슬롯 정책 선택 목록에서 제외 |
| `vr_standard_area_supplier.AREA_SEQ_NO` | 권역 FK |
| `vr_standard_area_supplier.SUPP_ID` | 소속 협력사 ID |

> 권역과 협력사는 N:M 관계. 수정 시 기존 매핑 전체 삭제 후 재삽입 방식으로 처리한다.

### 저장 로직 패턴

```java
// StandardAreaUseCase.saveStandardArea() — @Transactional + completedFuture 패턴
// 1. 수정 시: 기존 매핑 전체 삭제 (deleteByAreaSeqNo) → 신규 매핑 saveAll
// 2. 신규 시: area 엔티티 save → 매핑 엔티티 리스트 빌드 → saveAll

// ⚠️ 주의: mappings 리스트를 빌드만 하고 saveAll 호출을 빠뜨리면 매핑이 저장되지 않는다.
standardAreaSupplierRepository.saveAll(mappings); // 반드시 호출
```

### 자동 등록 로직

`StandardAreaUseCase.autoRegister(userId)`

- `vr_supplier_info`에서 전체 협력사 목록 조회
- `SUPP_NAME`에서 "부릉" 이전 문자열 추출 → 권역명으로 사용
  ```java
  String areaName = suppName.contains("부릉")
      ? suppName.substring(0, suppName.indexOf("부릉")).trim()
      : suppName.trim();
  ```
- 같은 이름의 권역이 없으면 신규 등록, 매핑도 없으면 신규 등록
- 이미 존재하는 권역/매핑은 건너뜀 (멱등성 보장)
- 반환: `{ newAreaCount, newMappingCount }`

## 주의사항

- `saveAll(mappings)` 누락 버그: 매핑 리스트를 빌드한 뒤 저장 호출을 빠뜨리면 DB에 반영되지 않는다. 반드시 `standardAreaSupplierRepository.saveAll(mappings)` 확인.
- `ConfirmModal`의 `onConfirm`은 동기 `() => void` 타입이므로 async 함수를 직접 전달하면 TS 오류 발생 → `void` 키워드 래핑 필요.
- 자동 등록 기능은 멱등성이 있어 중복 실행해도 이미 등록된 데이터는 건너뜀.
- 권역 삭제 시 `vr_standard_area_supplier` 매핑도 함께 삭제됨 (메시지로 사용자에게 안내).
