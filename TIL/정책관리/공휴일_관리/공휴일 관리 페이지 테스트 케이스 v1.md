# 공휴일 관리 테스트 케이스

작성일: 2026-07-28

---

## TC-1. 공휴일 등록

### TC-1-1. 정상 등록

**전제조건**: `vr_holiday` 테이블에 `2026-01-01` 없음

**입력**
```json
{
  "holidayDate": "2026-01-01",
  "holidayName": "신정",
  "targetDow": 7,
  "isSubstitute": "N",
  "userId": "admin"
}
```

**기대 결과**
- HTTP 200
- DB에 `HOLIDAY_DATE='2026-01-01'`, `TARGET_DOW=7`, `USE_YN='Y'` 행 생성

---

### TC-1-2. 중복 날짜 등록 시 오류

**전제조건**: `vr_holiday`에 `2026-01-01` 이미 존재

**입력**: TC-1-1과 동일

**기대 결과**
- HTTP 500 (UNIQUE KEY `uq_holiday_date` 위반)
- DB 기존 행 변경 없음

---

### TC-1-3. 필수 필드 누락

**입력** (holidayName 생략)
```json
{
  "holidayDate": "2026-01-01",
  "targetDow": 7,
  "isSubstitute": "N",
  "userId": "admin"
}
```

**기대 결과**
- HTTP 400
- 응답 메시지: `"공휴일명은 필수입니다"`

---

## TC-2. 공휴일 수정

### TC-2-1. targetDow 변경

**전제조건**: seqNo=1, `TARGET_DOW=7` 로 등록된 공휴일 존재

**입력**
```json
{
  "seqNo": 1,
  "holidayDate": "2026-01-01",
  "holidayName": "신정",
  "targetDow": 6,
  "isSubstitute": "N",
  "userId": "admin"
}
```

**기대 결과**
- HTTP 200
- DB에서 해당 행의 `TARGET_DOW=6`, `UPD_DATE` 갱신 확인

---

### TC-2-2. 존재하지 않는 seqNo 수정 시 오류

**입력**
```json
{
  "seqNo": 99999,
  "holidayDate": "2026-01-01",
  "holidayName": "신정",
  "targetDow": 7,
  "isSubstitute": "N",
  "userId": "admin"
}
```

**기대 결과**
- HTTP 500
- 메시지: `"공휴일을 찾을 수 없습니다: 99999"`

**기대 결과**

**요청**: `GET /api/v1/holiday?year=2026`

**기대 결과**
- 응답 `holidays` 배열에 seqNo=1 항목 미포함

## TC-5. 자동 동기화

### TC-5-1. 정상 동기화

**전제조건**: `vr_holiday` 테이블 비어 있음

**요청**: `POST /api/v1/holiday/sync/2026?userId=admin`

**기대 결과**
- HTTP 200
- `{ "year": 2026, "savedCount": N }` (N = nager.date에서 내려오는 2026년 한국 공휴일 수)
- DB에 2026년 한국 공휴일 전체 등록 확인
- 각 행의 `TARGET_DOW` = 해당 공휴일의 실제 요일 (예: 2026-01-01 목요일 → `TARGET_DOW=4`)

---

### TC-5-2. 이미 등록된 날짜는 건너뜀

**전제조건**: `2026-01-01` 이미 `USE_YN='Y'`로 등록

**요청**: `POST /api/v1/holiday/sync/2026?userId=admin`

**기대 결과**
- `savedCount`에 `2026-01-01` 미포함 (기존 데이터 변경 없음)

---

### TC-5-3. USE_YN=N인 항목 복구

**전제조건**: `2026-01-01`이 `USE_YN='N'`으로 존재

**요청**: `POST /api/v1/holiday/sync/2026?userId=admin`

**기대 결과**
- `savedCount`에 `2026-01-01` 포함
- DB에서 해당 행 `USE_YN='Y'`, `UPD_DATE` 갱신 확인

---

### TC-5-4. nager.date API 장애 시 오류 반환

**전제조건**: 네트워크 차단 또는 API 다운 상황 (테스트 환경에서 URL을 임시 변조)

**기대 결과**
- HTTP 500
- 메시지: `"공휴일 API 호출에 실패했습니다: ..."`
- DB 변경 없음

## TC-6. 대시보드 달성률 반영 (핵심)

> 슬롯 정책: SLOT1(아침) 목표 — 월~금=100, 토=50, 일=30

### TC-6-1. 공휴일 아닌 날 (기준선)

**조건**
- 조회 날짜: 2026-07-29 (수요일)
- 공휴일 아님
- 협력사 아침 실적: 80건

**기대 결과**
- 적용 목표: **수요일(3) = 100**
- 달성 여부: 미달 (80 < 100)

---

### TC-6-2. 공휴일 — TARGET_DOW=7(일)로 설정

**전제조건**: `vr_holiday`에 `2026-07-29, TARGET_DOW=7, USE_YN='Y'` 등록

**조건**
- 조회 날짜: 2026-07-29 (수요일이지만 공휴일)
- 협력사 아침 실적: 35건

**기대 결과**
- 적용 목표: **일요일(7) = 30** (실제 요일 수요일 무시)
- 달성 여부: 달성 (35 ≥ 30)

---

### TC-6-3. 공휴일 — TARGET_DOW=6(토)으로 설정

**전제조건**: `vr_holiday`에 `2026-07-29, TARGET_DOW=6, USE_YN='Y'` 등록

**조건**
- 협력사 아침 실적: 45건

**기대 결과**
- 적용 목표: **토요일(6) = 50**
- 달성 여부: 미달 (45 < 50)

---

### TC-6-4. 정책 있는 협력사 vs 없는 협력사 — 각각 적용

**전제조건**
- `vr_holiday`: `2026-07-29, TARGET_DOW=7`
- 슬롯 정책 A: 협력사 "안성A"에 매칭, SLOT1 일요일(7) 목표=20
- SLOTINFO 기본: SLOT1 일요일(7) 목표=30

**조건**
- 협력사 "안성A" (정책 있음): 아침 실적 25건
- 협력사 "청주B" (정책 없음): 아침 실적 25건

**기대 결과**

| 협력사 | 적용 목표 | 달성 여부 |
|--------|-----------|-----------|
| 안성A (정책 있음) | 정책 A의 val7 = **20** | 달성 (25 ≥ 20) |
| 청주B (정책 없음) | SLOTINFO val7 = **30** | 미달 (25 < 30) |

---

### TC-6-5. USE_YN=N인 공휴일은 반영 안 됨

**전제조건**: `vr_holiday`에 `2026-07-29, TARGET_DOW=7, USE_YN='N'` 등록

**조건**
- 조회 날짜: 2026-07-29 (수요일)
- 협력사 아침 실적: 35건

**기대 결과**
- 공휴일 무시 → 적용 목표: **수요일(3) = 100**
- 달성 여부: 미달 (35 < 100)

---

### TC-6-6. 조회 기간 내 일부 날짜만 공휴일

**전제조건**
- 조회 기간: 2026-07-27(월) ~ 2026-08-02(일) (1주일)
- `vr_holiday`: `2026-07-29(수), TARGET_DOW=7`만 등록

**기대 결과**
- 2026-07-27(월): 월요일 목표치 적용
- 2026-07-28(화): 화요일 목표치 적용
- **2026-07-29(수): 일요일(7) 목표치 적용** ← 공휴일
- 2026-07-30(목) ~ 2026-08-02(일): 각 실제 요일 목표치 적용
